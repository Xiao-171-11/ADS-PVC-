# SATA-01 · TC264 智能车完整程序（摄像头循迹 + 差速 + 速度闭环 + 舵机闭环）

按 B 站合集 **「智能车入门基础教学」（UP：WwuSama）第 13～25 集** 的流程写成的**可直接烧录运行**的完整程序。
**实车验证：已能稳定跑完整条赛道。**

- 引脚 ↔ 功能对照：见 [第 3 章](#3-引脚表引脚--功能)
- 哪些代码由 AI 生成：见 [第 7 章](#7-ai-生成代码声明)

- 主控：Infineon **TC264D**，开发环境 **AURIX Development Studio**
- 硬件：总钻风 MT9V03X（188×120）+ TFT180 + 双电机 + 舵机 + 双编码器
- 运行结构：
  - **主循环（≈50 fps）**：大津法二值化 → 边缘基点 → 边缘基线 → 加权中线（含互补滤波）
  - **5 ms 中断（200 Hz）**：编码器测速 → 速度环 PID → 差速 → 左右电机 PWM；中线偏差 → 舵机 PD → 舵机 PWM
  - 两者通过 `midline_info.error` 交换数据

## 4. 上车前必须做的 6 项标定

> 代码能跑，但**参数是通用初值**，按顺序做下面 6 步，车才会跑得稳。

| # | 标定项 | 怎么做 | 改哪里 |
|---|---|---|---|
| 1 | **方向** | 架空车，手动给正占空比看轮子转向；正转但读到的速度是负 → 改 `MOTOR_DIR_REVERSE_x` / `ENCODER_x_REVERSE` | `Motor_REMAIN.h`、`Encoder_REMAIN.h` |
| 2 | **舵机中值与方向** | 上电 3 秒内舵机应回中；给 `Servo_Set_Turn(20)` 看是否向右打角，反了改 `SERVO_REVERSE` | `Servo_REMAIN.h` |
| 3 | **基础速度** | 架空，看屏幕 `V`/`R`（标定期显示 `L`）；标定完把 `CONTROL_BASE_SPEED` 调到合适脉冲数。**前馈系数上电自动学，不用手填 `CONTROL_DUTY_BASE`** | `Control_REMAIN.h` |
| 4 | **后轮差速方向** | 架空，临时把 `error` 赋成 +50，看**后左轮**是否比**后右轮**快；反了改 `CONTROL_DIFF_REVERSE` | `Control_REMAIN.h` |
| 5 | **舵机比例** | 先 `SERVO_KD = 0`，把车放在赛道中间，逐步加大 `SERVO_KP` 直到能跟住弯道又不抖 | `Servo_REMAIN.h` |
| 6 | **速度环 PID** | 先 `KI=KD=0` 加 `KP` 到速度能跟上目标，再少量加 `KI` 消除静差 | `Control_REMAIN.h` |

### 速度闭环：前馈自标定

每个 5 ms 周期：**读编码器 → 算目标速度 → 前馈 + PID 修正 → 给占空比**。

```
目标速度 ──┬─► 前馈 gain_l/r × target + offset_l/r ──┐
           │                                 ├─► 占空比 ─► 电机
           └─► PID(目标 − 实测) ─────────────┘
实测速度 ◄───────────────────────────────────── 编码器
```

`offset` 是**静摩擦死区**（占空比低于它电机根本不转），`gain` 是斜率。两个都上电自动标，**而且左右轮各标一套**。

> **为什么必须左右分开标**：两个电机的减速箱效率、静摩擦、编码器线数都可能不一样。
> 实测这台车同一个占空比下 **左边读到 11、右边读到 80（差 7 倍）**。
> 共用一个系数的话，前馈给右轮的量比它实际需要的大 7 倍，PID 的 ±500 修正根本拉不回来，
> 结果就是一边爬一边飞、直道自己跑偏。分开标之后两轮各自闭环，占空比自然一个 1700 一个 900，速度却都是 10。

`gain`（占空比 / 速度）**上电自动学**，不用手填：

| 阶段 | 行为 | 屏幕 |
|---|---|---|
| ① 找死区 | 占空比从 `MIN`(800) 起，每 15 拍加 300，**直到左右两轮都真的转起来**；记下"转不动"的最后一档当死区参考，转到的那档记为 `d1` | `L`（绿） |
| ② 量第一点 | 保持 `d1`，丢前 0.15 s，取后 0.55 s 平均 → `s1_l` / `s1_r`（左右分开记） | `L` |
| ③ 量第二点 | 抬到 `d2 = d1 + 800`（远离死区），同样取平均 → `s2_l` / `s2_r` | `L` |
| ④ 两点定直线 | 左右各算一条：`gain_l = (d2 − d1) / (s2_l − s1_l)`、`offset_l = d1 − gain_l × s1_l`，右轮同理 | `G###` 两轮平均增益 |
| ⑤ 合理性校验 | 反算 `gain × BASE + offset`，超过 `CONTROL_FF_DUTY_AT_BASE_MAX`(4000) 说明标定时轮子根本没转，这组系数作废重标 | `E` |
| ⑤ 爬到 4000 还不转 | 判**编码器没信号 / 电机没供电** → 停车 0.5 s 后重试（最多 5 次） | `E`（红） |

> **为什么必须测两个点**：只在一个点量，而那个点通常就贴着死区边（速度才 2~3），
> 斜率会被放大好几倍 —— 死区 1000、真实斜率 40 的电机，单点能算出 **120**，一给油车就窜。
> 两点拉开 800 占空比之后再算，四种典型电机都能量到真值（60/40/20/100），稳态速度误差 < 0.5 %。

> **为什么要"爬占空比"而不是给固定值**：带减速箱的小车，6% 占空比（500/8000）是**拖不动**的。
> 旧版固定给 500，轮子一动不动 → 量到 0 速度 → 误判成"编码器坏了"直接停车。
> 现在从 8% 起步逐级加，只要轮子一转就停在该档，既不会窜也不会误判。

> **屏幕怎么看标定结果**：最底行 `V### R### G###`。标定中第二位显示绿 `L`；成功 `L` 消失，
> `V`/`R` 应该都贴着 `CONTROL_BASE_SPEED`（默认 **75**），差 1~2 正常。**两轮差 3 倍以上就是没分开标或编码器线数不同**。
>
> **不再每次标定**：`CONTROL_FF_LEARN_EN = 0` 时上电直接用 `g7.0/8.0`、`b529/484` 这套实测系数，1 s 后就起步。
> 换电机、换电池、改轮胎、改地面材质之后，把它改回 **1** 重新标一次，再把屏幕 `g/b` 的四个数抄进默认宏。
> 红色 `E` 常亮 = 5 次标定都失败（车还会跑，前馈用兜底值），先查编码器接线。

**闭环开关判据**：上电那 3 s 发车延时里电机是断电的，程序顺手统计这段时间的脉冲数。
静止却一直有脉冲 = 编码器线被电机 PWM 干扰，闭环读数不可信，此时屏幕最右会出现 **`n`**，
车自动退回 v1.0 的固定占空比开环跑（不会飞出去），需要先修线：编码器线远离电机线、双绞、
信号对地并 100 nF。

### 编码器自检（怀疑编码器有问题时做这一步）

1. `code/Control_REMAIN.h` 里把 `CONTROL_ENCODER_TEST_EN` 改成 **1**，重新编译烧录；
2. 上电 3 s 后电机不会转，屏幕最下面一行 `V### R###` 就是**每 5 ms 的原始脉冲数**；
3. 用手慢慢转动左后轮：`V` 应该变成正数（向前）或负数（向后）；右后轮看 `R`；
4. 手停住时两个数应该**稳定在 0 或 ±1**。如果手不动还在跳几十个数 → 接口悬空或受干扰，
   先查接线（信号线是不是接到了 `P20_3` / `P10_3`，地线有没有接）；
5. 测完记得把宏改回 **0**。

**第 6 行 `gL/gR bL/bR`**（图像关掉时才显示）直接给出标定出来的四个数，判断标准：

| 读数 | 判断 |
|---|---|
| `b` 在 700~1100 | 正常（这就是静摩擦死区） |
| `b` 顶到 1200 | 标定时轮子被卡住过，这次结果不可信 |
| `g` 两百轮差好几倍 | 正常，两个电机本来就不一样 |
| `g` 都只有 20 上下 | 正常（占空比/速度） |
| `g` 80 以上 | 标定时两点速度几乎没拉开（轮子被手挡了/压在垫子上），重标 |

| 宏 | 默认 | 含义 |
|---|---|---|
| `CONTROL_FF_LEARN_TICKS` | **140** | 每个测量点 140 拍（0.7 s） |
| `CONTROL_FF_LEARN_SKIP` | **30** | 前 30 拍不计入平均（0.15 s，丢启动瞬态） |
| `CONTROL_FF_LEARN_BOOST` | **800** | 第二测量点比第一点再高多少（离死区越远斜率越准） |

| `CONTROL_FF_LEARN_DUTY_MAX` | **4000** | 爬到这儿还不转就判故障 |
| `CONTROL_FF_LEARN_STEP` / `RAMP_TICKS` | **300 / 15** | 每 15 拍加 300 占空比 |
| `CONTROL_FF_MIN_SPEED` | **1.5** | 认"转起来了"的速度门限 |
| `CONTROL_FF_GAIN_MIN/MAX` | **2 / 400** | 标定结果限幅，防编码器异常给出离谱系数 |
| `CONTROL_ENC_FAULT_DUTY` | **1200** | 判"电在使劲"的占空比门限（15%，正常慢速不会触发） |
| `CONTROL_ENC_FAULT_TICKS` | **200** | 有劲没速度持续 200 拍（1 s）→ 判掉线 |
| `CONTROL_ENC_CUT_TICKS` | **100** | 判掉线后停车 0.5 s **再自动重试**，不锁死 |

> **`E` 怎么看**：`E` **闪烁** = 标定失败正在重试（多数是上电瞬间没读到速度，一次就过）；
> `E` **常亮** = 连续 5 次都失败，此时车**照常跑**（用默认增益 + 8 % 死区补偿），
> 但前馈不准、速度会偏 —— 先查编码器接线、电池和电机驱动供电。
> 标定全流程约 **2 秒**（爬占空比 0.55 s + 两个测量点各 0.7 s）。

### 舵机打角参数（`Servo_REMAIN.h`）

分段增益：直道用小增益（不摆），弯道用大增益（打得动）。

| 宏 | 默认 | 含义 |
|---|---|---|
| `Servo_MID` / `SERVO_TRIM` | **464** / 0 | 中值 + 中值微调（车直道往哪边偏就往反方向调几个数）。实测 465 整体偏右，定 464 |
| `SERVO_DUTY_RANGE_L` | **70** | 向左最大偏移 → 占空比上限 **534** |
| `SERVO_DUTY_RANGE_R` | **69** | 向右最大偏移 → 占空比下限 **395** |
| `SERVO_DUTY_RANGE` | 70 | 兼容旧名字（= L）。**已不再使用**，新代码请用 `_L` / `_R` |

> **机械行程必须按实测填。** 这版把左右拆成两个宏，是因为实测舵机只能到 **395 ~ 534**（中值 464，左 +70、右 −69，左右不对称）。`Servo_Set_Duty()` 里对任何指令都做左右分别限幅，超出范围一律夹回来，所以舵机不会再顶在机械死点上堵转发烫。换舵机/改连杆后要重新量一遍：
>
> 1. 把车架空，`Control_REMAIN.h` 里 `CONTROL_SPEED_LOOP_EN` 改 0、`CONTROL_DUTY_BASE` 改 0（轮子不转）；
> 2. 临时在 `SATA_MAIN()` 里 `Servo_Init();` 之后写 `Servo_Set_Duty(464+80);`，烧进去听声音——**开始嗡嗡响、发烫的那个值就是死点**；
> 3. 往回收 8~10 个数写入 `SERVO_DUTY_RANGE_L`；再用 `Servo_Set_Duty(464-80);` 同样测 `_R`；
> 4. 中值：`Servo_Set_Duty(464);` 时前轮应正对车头，偏了就把 `Servo_MID` 加减 1~2，或改 `SERVO_TRIM`。
| `SERVO_DEAD_ZONE` | **3.0** | 死区：偏差 < 3 像素不动作，治直道抖动 |
| `SERVO_KNEE` | **8.0** | 拐点：8 像素以内小增益，以外大增益 |
| `SERVO_KP_NEAR` | **1.2** | 小偏差增益（直道靠它稳住，别轻易加大） |
| `SERVO_KP_FAR` | **4.0** | 大偏差增益（打满行程所需偏差 37 → 22.5 像素） |
| `SERVO_KD` | **2.0** | 微分阻尼，压住来回摆（0 = 关） |
| `SERVO_REVERSE` | 0 | 左右打角反了改 1 |

打角曲线实测（`1.2 / 8 / 4.0`，中值 464，机械行程 70）：

```
error     0    3    5    8   12   16   20   22.8  >=22.8
打角量    0    0    6  9.6   26   42   58     70     70
占空比  464  464  458  454  438  422  406    394    394
占满      0%   0%   9%  14%  37%  60%  83%  100%   100%
```

直道上真正的偏差只有几像素，还会逐帧抖 1~3 像素。所以除了增益分段，还做了两件事：

1. **偏差低通** `SERVO_ERR_FILTER = 0.65`：`error = 0.65*本次 + 0.35*上次`，抖动幅度砍掉约一半；
2. **出弯保持必须有"真弯"**：`SERVO_ARM_ERROR = 30` 且这一弯峰值 ≥ `SERVO_HOLD_MIN_PEAK = 30` 才允许锁——以前直道上一次 20 像素的扰动就会把满舵锁住 0.2 s，那正是"直道突然大角度修正"的来源。

仿真对比（直道真值 ±8 像素漂移 + 2 像素逐帧噪声，200 帧）：

```
                     输出峰值   RMS   反向次数
旧版(无滤波 1.5 死区2)   20.6    8.0     142
新版(滤波0.65 1.2 死区3) 12.1    4.3     132
```

峰值降 41%、RMS 降 46%，而弯道响应不变（25 像素阶跃两边都是立刻满舵 70）。

**为什么调这么陡**：车在弯里贴外沿跑、甚至冲出去，本质是"打角来得太晚"——
偏差必须攒到 **37 像素**（旧版）才给满舵，而弯道中的偏差本来只有十几像素，
于是车只会轻轻转，一路被推到外沿。现在 **22.5 像素就满舵**，20 像素已有 86%，
车能提前咬住弯心。直道 5 像素仍只给 11%，不会左右摆。

> **改车速改哪个**：`CONTROL_SPEED_LOOP_EN = 1`（闭环）时改 `CONTROL_BASE_SPEED`，PID 会把实际速度拉到目标；
> `= 0`（开环）时改 `CONTROL_DUTY_BASE`。两个一起按同一比例改最稳（前馈和目标匹配，PID 不用使劲）。
> **当前这一版 = 上一轮再降 50%**：20→10、1200→600、35→18、1000→500、5→3。

### 出弯保持：不马上回中

**问题**：车头刚摆正的瞬间如果舵机立刻回中，车会继续沿原来那条弧线往外推，表现就是"出弯冲出去"。

**做法**：偏差连续 10 拍（50 ms）超过 40 就算"进弯"，期间一直记住这一弯的最大打角；偏差掉到 15 以下认为"刚出弯"，把这一弯的**最大打角**锁住（不超过机械行程 70），在 40 拍（0.2 s）内**线性退回中位**。这 0.8 s 里车还在弯道出口，方向保持住，车头能摆正再走直道。

| 宏 | 默认 | 说明 |
|---|---|---|
| `SERVO_EXIT_HOLD_EN` | **1** | 0-关掉出弯保持（回到原来立刻回中） |
| `SERVO_HOLD_TICKS` | **40** | 保持时长，40 × 5 ms = 0.2 s |
| `SERVO_HOLD_DECAY` | **1** | 1-保持期间线性回中；0-恒值保持到最后一拍才跳回 |
| `SERVO_ARM_ERROR` | **30.0** | 偏差超过它算进弯（像素） |
| `SERVO_HOLD_MIN_PEAK` | **30.0** | 这一弯的峰值没到 30 就不许锁保持（防直道小抖动被锁成满舵） |
| `SERVO_ERR_FILTER` | **0.65** | 偏差低通系数：`0.65*本次 + 0.35*上次`，压掉直道逐帧抖动 |
| `SERVO_ARM_MIN_TICKS` | **10** | 连续超过 50 ms 才算真进弯，防止擦边误触发 |
| `SERVO_RELEASE_ERROR` | **15.0** | 偏差掉到它以下算出弯，开始保持 |

**调法**：

- 出弯还是往外推 → `SERVO_HOLD_TICKS` 加（40 → 80，0.4 s）；
- 出弯往内侧切 / 进下一个弯反应慢 → `SERVO_HOLD_TICKS` 减（40 → 20，0.1 s）；
- 直道上车被"拖"一下才回正 → `SERVO_RELEASE_ERROR` 从小改大（15 → 20），或 `SERVO_HOLD_MIN_PEAK` 加大（30 → 40），让直道根本锁不住保持。
- 保持期间如果偏差**反向**且超过 `SERVO_RELEASE_ERROR`（车已经被往另一边推），代码会立刻放弃保持、交回正常打角——不会把车顶出赛道。

### 十字路口：强制直行

**问题**：路口两条横臂会被当成左右边线，算出来的"赛道宽度"翻倍，中线跑到赛道外，偏差几十像素。再叠加"出弯保持"（出弯那 0.2 s 还在按弯道打角），车就从路口对角冲出去 —— 这就是"过弯后紧接路口会冲出赛道"的成因。

**做法**（`Find_MIDLine()` 末尾）：

| 判据 | 阈值 | 说明 |
|---|---|---|
| 主判据 | `width > 学习宽度 × 1.25` | 路口横臂张开，实测宽度突然翻倍 |
| 次判据 | `有效行 < 12` **且** `width > ×1.10` | 边线在路口断掉 |
| 否决条件 | `|error| > 30` | 中线已经偏出中心 → 那是弯道，不是路口 |

连续 2 帧可疑 → 认定路口 → **锁定 40 帧（约 0.4 s）**，期间强制 `center = 94`、`error = 0`；连续 5 帧恢复正常则提前解锁。锁定期间**不改写 `last_mid_line`、不学习赛道宽度**，路口结束滤波从进来前的状态续上，不会被假中线污染。

同时 `Control_Tick()` 在路口调用 `Servo_Clear_Hold()`，把"出弯保持"立刻取消，避免带着弯道的打角冲进路口。

| 宏（`MIDLine_REMAIN.h`） | 默认 | 说明 |
|---|---|---|
| `MIDLINE_CROSS_EN` | **1** | 0-关掉路口识别 |
| `MIDLINE_CROSS_WIDTH_RATIO` | **1.25** | 主判据倍率 |
| `MIDLINE_CROSS_NARROW_RATIO` | **1.10** | 次判据的宽度下限 |
| `MIDLINE_CROSS_FEW_ROWS` | **12** | 次判据的行数上限 |
| `MIDLINE_CROSS_CENTER_TOL` | **30.0** | 中线偏出多少就不算路口 |
| `MIDLINE_CROSS_LOCK_TICKS` | **40** | 锁定帧数（约 0.4 s @100 fps） |
| `MIDLINE_CROSS_EXIT_TICKS` | **5** | 连续正常几帧提前解锁 |

**调法**：

- 路口还是冲出去 → 把 `MIDLINE_CROSS_WIDTH_RATIO` 降到 **1.15**（更容易判成路口）；
- 弯道里被误判成路口（车在弯里突然直冲） → 把 `CENTER_TOL` 降到 **20**，或 `WIDTH_RATIO` 抬到 **1.35**；
- 路口太早就解锁（车还在路口里就开始打角） → `LOCK_TICKS` 40 → 60，`EXIT_TICKS` 5 → 8。

屏幕 `C` 行最右边出现 **`X`** 就表示这一帧判成路口、正在直行。

### 斑马线起停（起点 / 终点）

赛道的黑色斑马线既是起点也是终点：**上电后看到斑马线才发车，跑完一圈再看到斑马线就停**。

**识别方法**（`Zebra_REMAIN.c`）：在二值图的 **82~118 行**（车头前 0.25~0.9 m）横向扫行，数"宽度 2~22 px 的暗游程"—— 斑马线是十几根窄黑条，普通赛道边线是两根宽黑带、且不在这一段密集出现。

| 判据 | 阈值（`Zebra_REMAIN.h`） | 说明 |
|---|---|---|
| 单行黑条数 | `ZEBRA_MIN_BARS = 5` | 一行里至少 5 根窄黑条 |
| 单行白占比 | `ZEBRA_WHITE_MIN = 0.25` | 白底要够多，排除全是黑条的阴影 |
| 条宽范围 | `ZEBRA_BAR_MIN_PX = 2` ~ `ZEBRA_BAR_MAX_PX = 22` | 太细是噪声，太粗是赛道边线 |
| 命中行数 | `ZEBRA_MIN_ROWS = 3` / `ZEBRA_HIT_FRAMES = 2` | 连续两帧命中才算 |

**状态机**（三态）：

| 状态 | 含义 | 转换条件 |
|---|---|---|
| 0 | 等待发车（电机断电、舵机回中） | `hit_cnt >= 2` → 1 |
| 1 | 行驶中 | `clear_cnt >= 25` **且** `run_cnt >= 150` 先置 `armed = 1`；之后 `armed && hit_cnt >= 2` → 2 |
| 2 | 到达终点（锁死） | 只有重新上电才回 0 |

> **`armed` 为什么必须有**：刚发车时车还压在斑马线上，不先"跑过去并看清一段时间"就会被自己判成终点停死。`ZEBRA_RUN_MIN_FRAMES = 150`（约 1.5 s）与 `ZEBRA_CLEAR_FRAMES = 25` 就是这段"跑开"的门槛。

**接入位置**：

- `Control_REMAIN.c` 的发车条件：`#if (1 == ZEBRA_EN) if((0 == zebra_info.state) || (2 == zebra_info.state) || (发车延时未到))` —— 等待期间电机断电、舵机回中，同时**顺手测编码器噪声底**（原来那 1 s 延时干的活一点没丢）；
- `SATA_MAIN.c`：`Zebra_Init()` 在 `MIDLine_Init()` 之后；`Zebra_Scan()` 在 `Camera_Process_Once()` 之后（必须先有二值图和阈值）；`Zebra_Show_On_TFT180()` 在显示段；
- 阈值复用大津法结果：`Camera_REMAIN.c` 每帧把 `threshold` 存进 `camera_threshold`，斑马线模块直接读，**不重复算一遍**。

**屏幕**：第 1 行最右边一个字 —— 黄 `W` 等待发车 / 绿 `R` 行驶中 / 红 `F` 到达终点。

**调法**：

- 起步不触发（车不动） → `ZEBRA_MIN_BARS` 5 → **4**，或 `ZEBRA_MIN_ROWS` 3 → **2**；
- 跑起来被误判成终点停了 → `ZEBRA_RUN_MIN_FRAMES` 150 → **300**，`ZEBRA_CLEAR_FRAMES` 25 → **50**；
- 终点没停 → `ZEBRA_RUN_MIN_FRAMES` 150 → **80**，`ZEBRA_MIN_BARS` 5 → **4**；
- 完全不想用斑马线 → `ZEBRA_EN` 改 **0**（回到纯 1 s 延时发车、不停车）。

### 后轮差速模型

车是「**舵机转前轮 + 双电机驱动后轮**」，所以差速只作用在**后左 / 后右**两个驱动轮之间：

```
ratio  = CONTROL_DIFF_K × error           // 偏差 -> 速度比例，±CONTROL_DIFF_K_MAX 限幅
v_后左 = 基础速度 × (1 + ratio)            // 外侧
v_后右 = 基础速度 × (1 - ratio)            // 内侧
```

方向：`error > 0` 表示赛道中心在图像右侧 -> 车要**右转** -> 后左轮是**外侧**（走的路更长）-> 左快右慢。
用「比例」而不是「固定差值」：真实的内外轮比由转弯半径决定，`v_外 / v_内 = (R + W/2) / (R − W/2)`，
车速一提，同样的打角就需要更大的轮速差，比例模型自己就跟着放大了，不用重调参数。

| error | ratio | 后左 / 后右（基础速度 **25**，当前设置） |
|---|---|---|
| −94（赛道偏左） | −0.376 | 6.2 / 13.8 |
| −30 | −0.120 | 8.8 / 11.2 |
| 0 | 0 | 10.0 / 10.0 |
| +30 | +0.120 | 11.2 / 8.8 |
| +94（赛道偏右） | +0.376 | 13.8 / 6.2 |

**两个必须注意的点**：

1. **机械差速**：后桥如果还装着机械差速器，它本身已经按转弯半径把速度分给两轮，电子差速是**叠加**在它上面的，实际轮速差会偏大、车会往弯里扎。处理办法二选一：把 `CONTROL_DIFF_K` 减小 30%~50%，或者干脆锁死机械差速（直轴）只用电子的。
2. **外侧轮被限速**：`CONTROL_SPEED_MAX` 必须 ≥ `CONTROL_BASE_SPEED × (1 + CONTROL_DIFF_K_MAX)`。当前 75 × 1.5 = 112.5 ≤ 112.5，刚好够；再提速时这两个数要一起改，否则外侧轮被削平、车往弯外推。

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| **直道频繁大角度修正** | 直道小抖动被高增益放大；或出弯保持被小扰动误锁 | 先看 `SERVO_HOLD_MIN_PEAK` 是否为 30；再降 `SERVO_KP_NEAR`（1.2→1.0）、升 `SERVO_ERR_FILTER`（0.65→0.5 更平滑）、`SERVO_DEAD_ZONE` 3→4 |
| **弯里一直贴外沿 / 冲出赛道** | 打角来得太晚（打满所需偏差太大） | 加大 `SERVO_KP_FAR`（4.0→5.0）或减小 `SERVO_KNEE`（8→6）；同时把 `CONTROL_CURVE_SLOW_MIN` 降到 0.4 |
| **过弯时卡住 / 停在弯里** | 弯道丢线 1 秒触发停车保护；或弯里速度太高打不动方向 | `CONTROL_LOST_STOP_TICKS` 已改 **0**（不再停车）；再不行把 `CONTROL_CURVE_SLOW_MIN` 从 0.6 降到 0.5，让弯道更慢 |
| **原地转圈 / 两个后轮转向相反** | 左右电机方向脚极性不一致（实测：右后轮正转、左后轮倒转） | 把转反的那一侧 `MOTOR_DIR_REVERSE_x` 改成 1，架空复测两轮同向 |
| 车跑起来了但屏幕最底一行 `V` 一直是 `000` | 编码器没接对 / 定时器选错 / `ENCODER_x_REVERSE` 极性 | 先把 `CONTROL_SPEED_LOOP_EN` 改 0 用开环跑，再逐路查编码器 |
| 车轮向前滚，`V`/`R` 却是**负数** | 编码器 A/B 相接反或计数方向相反 | 把 `ENCODER_L_REVERSE` / `ENCODER_R_REVERSE` 改 **1** |
| 架空时后轮完全不转，屏幕右下角有 `E` | 标定爬到 4000 还没读到速度 | 先确认电池、电机驱动供电；再确认手推车轮时 `V`/`R` 有正数变化 |
| 上电 3 秒后车不动 | 没有图像 / `midline_info.valid` 一直是 0 | 看屏幕：有 `TH` 数值说明图像在跑；`CAMERA ERR` 说明摄像头没配好 |
| 车往反方向打角 | 舵机方向 | `SERVO_REVERSE` 改 1 |
| 过弯紧接路口冲出去 | 路口被当成宽赛道，或出弯保持还在打角 | 屏幕 `C` 行有没有 `X`：没有就把 `MIDLINE_CROSS_WIDTH_RATIO` 降到 1.15；有 X 还冲就降 `CONTROL_CURVE_SLOW_MIN` |
| 出弯还是冲出去 | 出弯保持不够 | `SERVO_HOLD_TICKS` 40 → 80，或把 `SERVO_RELEASE_ERROR` 抬到 20（更早开始保持） |
| 出弯往内侧切进去 | 保持太久 / 打角太大 | `SERVO_HOLD_TICKS` 40 → 20，或 `SERVO_HOLD_DECAY` 保持 1（本来就是线性回中） |

| 弯道跟不上 / 甩出去 | `SERVO_KP_FAR` 偏小 / `CONTROL_DIFF_K` 偏小 | 逐步加大，注意不要抖 |
