## 1. PID 的三种写法：位置式 / 增量式 / 只是 PD

| | 我们 `Control_REMAIN.c:24-121` | USTB_Swan `control.c:71-105` | ZongZuanFeng `PID.c:12-69` |
|---|---|---|---|
| 舵机环 | **位置式 PD**（Ki=0）+ 双段 Kp + 出弯保持 | **位置式 PID**，实为 PD（`integral_max=min=0`，积分两行被注释 `control.c:76-78`） | **位置式 PD**，角度域限幅 9~132° |
| 速度环 | **位置式 PID** + 前馈 | **增量式 PID**（`PID_spd`） | **增量式 PI** |
| 定点/浮点 | 全整型 | 全整型，`PID_SCALE=100`，增益=宏/100 | 全 float |
| 微分 | `kd*(e-last_e)`，**未低通** | 同，未低通；另配 `Kdd` 二阶项 | 无 D（PI） |
| 积分限幅 | clamping：`integral_max = out_max/ki` | 无（增量式天然靠输出限幅） | 无（只钳输出 ±100） |

### 1.1 USTB 的二阶项是个死配置（别抄）
```c
// control.c:85-87
pid->preError = error;
pid->prePreError = pid->preError;   // ← 先更新 preError 再赋给 prePreError
```
赋值顺序颠倒 → `prePreError` 恒等于新 `error`，于是 `Kdd*(error-2*preError+prePreError)` 退化成 `Kdd*(error-error_old)`，和 `Kd` 项完全重复。**`Kdd` 调多大都没用**。正确写法必须交换这两行（或先存 `prePreError = preError; preError = error;`）。

### 1.2 增量式的正确形态（USTB 速度环，可直抄）
```c
// 方向：output 是"这一次该给 PWM 加多少"，积分作用天然存在于累加值里
delta = (Kp*(e-e1) + Ki*e + Kd*(e-2*e1+e2)) / SCALE;
prePreError = preError;  preError = e;      // 顺序不能反
pwm += delta;                                // 真正的积分发生在这一行
```
优点：**不需要积分限幅**，输出限幅即抗饱和（USTB 就是这么做的，`control.c:321-340`）；缺点：目标突变时靠 `Kp*Δe` 吃冲击，起步要预载（`control.c:354-355` 停机时把 `motor_pwm` 预置 2000）。

### 1.3 结论
- **速度环**：现在的位置式 + 前馈其实是对的（有 `gain/offset` 前馈时位置式抗扰更好），**问题不是形式而是没斜坡、微分未滤**。想换增量式也行，但前馈就得改成"斜坡给目标、PI 只补差"。
- **舵机环**：保持 PD，**把 D 换成陀螺仪角速度**（见 §4.2），这才是质变。

## 2. 限幅：从"对称 ±500"到"四象限非对称"

### 2.1 USTB 的做法（`control.c:321-340`）
```c
if (motorPID.feedback > motorPID.target)          // 已经超速 → 只允许刹车
    motor_pwm = CLAMP(motor_pwm, -9999, target*13);
else                                              // 还没到速 → 基本放开
    motor_pwm = CLAMP(motor_pwm, -1000,    9999);
```
含义：**上限随目标速度自缩放**（`target*13` 是"这个目标速度下能用的最大占空比"，经验斜率），超速时把正向写死、负向（刹车）全开；未达速时反过来。等于把"电机的加速能力 vs 刹车能力不对称"直接写进限幅器，不需要额外的刹车逻辑。

坑：`control.c:335` 右轮那行误写 `motorPID_L.target*13`（复制粘贴 BUG），并且 `CLAMP` 宏不校验 `min<max`，目标为负时靠三元判断顺序"碰巧"正确。

### 2.2 ZongZuanFeng：输出百分比钳位
`PID.c:66-67` 只把 `Output` 钳到 ±100（=0~100% 占空比），没有按目标缩放 —— 这正是它起步"肉"、刹车"软"的原因。

### 2.3 落到我们身上（`Control_REMAIN.c:102-121`）
```c
/* 现在 */
out = pid_calc(&speed_pid_l, target_l, actual_l);        // 对称 ±500
duty_l = gain_l*target_l + offset_l + out;  clamp 8000
/* 改成 */
duty_l = feedforward + out;
if (actual_l > target_l)  duty_l = CLAMP(duty_l, -MOTOR_DUTY_MAX, ff_l + CTRL_BRAKE_HEADROOM);   // 超速：只留刹车方向
else                      duty_l = CLAMP(duty_l, ff_l - CTRL_BRAKE_HEADROOM, MOTOR_DUTY_MAX);
```
`ff_l = gain_l*target_l + offset_l`，`CTRL_BRAKE_HEADROOM` 取 1500~2500。

## 3. 速度斜坡：加速慢、减速快（1 : 25）

USTB `schedule.c:308-327`（原文行号见子代理笔记 308-327，头文件声明 `schedule.h:59`）：
```c
int16_t Speed_Ramp(int16_t target)
{
    if (search_speed_cmd == 0) return 0;        // 停车不过斜坡，立刻 0
    if (search_speed_ref < target) { search_speed_ref += up_step;   ... }   // up_step   = 1
    else if (search_speed_ref > target) { search_speed_ref -= down_step; ... } // down_step = 25
    return search_speed_ref;
}
```
- **上升 1 / 下降 25**，即 25 倍不对称：加速靠缓慢加占空比（防打滑丢线），减速直接砍目标让电机自己刹。
- 调用点在 200 Hz 控制里（`control.c:268`），5 ms 一步：`1*75/5ms` ≈ 满量程 75 需要 375 ms；减速 25/step ≈ 15 ms 见底。
- 斜坡之后才做 `CLAMP(±speed_straight)`（`control.c:269`），顺序不能反。

我们目前**完全没有斜坡**：`Control_REMAIN.c` 里 `CONTROL_BASE_SPEED` 直接乘 `slow` 系数（`Control_REMAIN.h:95-97`）后送进 PID，占空比阶跃 → 起步打滑、弯道减速时"点头"。

**落地骨架**（放 `Control_REMAIN.c`，5 ms 调用一次）：
```c
#define CTRL_SPEED_UP_STEP    (0.6f)    /* 每 5ms 允许增加的目标速度（脉冲） */
#define CTRL_SPEED_DOWN_STEP  (6.0f)    /* 每 5ms 允许减少（≈10 倍不对称） */
static float speed_ref = 0;
static float speed_ramp(float target) {
    if (target <= 0) { speed_ref = 0; return 0; }          /* 停车直落 */
    if (speed_ref < target) { speed_ref += CTRL_SPEED_UP_STEP;  if (speed_ref > target) speed_ref = target; }
    else                    { speed_ref -= CTRL_SPEED_DOWN_STEP; if (speed_ref < target) speed_ref = target; }
    return speed_ref;
}
/* 用法：v_内/v_外 由 speed_ramp(目标) 得到，再喂 PID */
```

### 3.1 减速的另一种写法（ZongZuanFeng `PID.c:52-57`，把减速做进目标）
```c
abs_err = min(|pos_err|, 100);
target  = (abs_err <= 5) ? str_spd
                         : MinSpeed + (str_spd - MinSpeed)*(100 - abs_err)/100;
```
按偏差线性插值到 `MinSpeed`，比我们的 `slow = clamp(1-0.008*|e|, 0.45, 1)` 多了一个**硬下限**（内侧轮不会掉到 0），且和 `abs_err` 的量程（100 像素）绑定，参数更直观。

## 4. 方向环：三条路，我们走在最"手工"的那条

| | 我们 `Servo_REMAIN.c:80-198` | USTB_Swan `control.c:426-450` | ZongZuanFeng `PID.c:12-28` |
|---|---|---|---|
| 形式 | PD，输出 raw duty | PID(实为 PD) + **陀螺 D 独立减项** | PD，输出角度 |
| Kp | **双段**：`|e|≤8 → 1.2`，之后 `1.2*8+4.0*(|e|-8)` | 400（=4.00，`PID_SCALE=100`） | 1.5 |
| Kd | 2.0，作用于图像偏差差分 | 1400（=14.00）图像差分；**另加** `gyro_d` | 0.4 |
| 死区 | 3 px（只把偏差置零） | 输出 `|out|<5 → 0` | 3 px（**直接回中**） |
| 限幅 | raw：左 +70 / 右 −69 | `SERVO_MID ± 190`（≈±21°） | 角度域 9~132°（中值 80） |
| 附加 | 出弯保持：锁峰值 40 拍线性衰减 | 无 | 无 |
| 接口 | `Servo_Set_Turn(error)` | `SERVO_SetPwmDuty(pin, duty)` | `Servo_SetAngleDeg(deg)` |

### 4.1 我们的双段 Kp 是被逼出来的
因为图像偏差 `error` 是**全图加权平均**（§5），弯道里它的幅值被"平均"压小，只好在 `|e|>8` 后把增益从 1.2 硬拉到 4.0 来补偿。**一旦换成前瞻加权（§5.1），双段就该退回单段**，否则急弯会过冲。

### 4.2 用陀螺仪替代图像微分（最值得抄的一条）
USTB 把"方向环的 D"拆成两半：图像 D（Kd=1400）负责趋势，陀螺 D 负责阻尼，两者**独立标定**。
```c
/* turning() control.c:426-450 */
servoPID.feedback = turn_line;
PID_Calc_Pos(&servoPID);
Cal_Gyro_Damp();                    /* → gyro_d */
servoPID.output -= gyro_d;          /* 直接减，不进 PID */
if (ABS(servoPID.output) < 5) servoPID.output = 0;
servo_duty = SERVO_MID - servoPID.output;

/* Cal_Gyro_Damp() schedule.c:230-245 */
gz_int = gyro_damp_k * posture.gz;                 /* gz 单位 °/s（/16.4 换算） */
if (gz_int > 200 || gz_int < -200)                 /* 2.00°/s 死区 */
    gyro_damp = CLAMP(gz_int * GZ_DAMP_KD(4) / 100, -100, 100);   /* 限幅 ±100 */
else { gyro_d = 0; return; }
gyro_d = gyro_damp / 8;
```
为什么有效：图像 D 天生有 **1~2 帧延迟 + 量化噪声**（我们 50 fps → 20 ms），而陀螺是 1 kHz 级、无延迟；用车体角速度做阻尼，等于给转向加了"防抖油"，这是纯图像方案做不到的。

**落地**：我们库里 `zf_device_imu660ra.c` / `icm20602.c` 都在（`libraries/zf_device/`），一个 `imu660ra_init()` + 5 ms 读一次 `gyro_z` 即可。代码见 `03-改造清单.md` §A3。

### 4.3 出弯保持：我们独有的资产，别丢
`Servo_REMAIN.c:113-194` 的"武装→锁峰值→40 拍线性衰减"补偿的是舵机机械延迟，USTB 和 ZongZuanFeng 都没有等价物。**加了陀螺阻尼后保持时间要缩短**（阻尼已经承担了一部分滞后补偿），建议 `40 → 20` 拍起调。

## 5. 前瞻：三种完全不同的加权哲学

| 方案 | 权重 | 前瞻长度 | 出处 |
|---|---|---|---|
| 我们 | `w[row] = 1 + 0.2*row`（row 自顶部起算，**越靠车头越大**） | 不可调，全图 | `MIDLine_REMAIN.c:65` |
| USTB | `w = line² + 1`（line=距底部行数，**越远越大**），且只统计 `line ≤ turn_height(41)` 的行 | `turn_height = TURN_HEIGHT_ORI(82)/IMG_ZIP(2) = 41`（处理图 56 行里取 41 行） | `search.c:2861-2883` + `calculate.c:760-778` |
| ZongZuanFeng | 不做加权，直接在 **40/41/42 行**里选一行作前视行算 Err | 一个常数 | `Camera.c` 取 Err 段 |

### 5.1 USTB 的加权公式（`calculate.c:760-778`）
```c
uint32_t get_weight(uint8_t line, uint8_t height) {
    if (line <= height) return line*line + 1;          /* 平方加权：远=重 */
    else                return (line*line)/(line-height) + 1;
}
```
配合 `calcTurnLine()` 的**等距选点**（相邻点 x 或 y 差 <2 就跳过，`search.c:2871`），避免"补线补出来的密集点"把权重吃满。

对比效果（我们的图 120 行、USTB 处理图 56 行，都换算成"距车头的相对高度 h∈[0,1]"）：
- 我们：`w = 1+0.2*h*120 = 1+24h` → 远端最多 25 倍，且是线性；
- USTB：`w = (41h)²+1 = 1681h²+1` → 远端 1682 倍，是平方。
**平方 + 截断高度 = 把控制量几乎全部押在"看得最远的那几行"上**，这就是"看远"的具体实现方式。`turn_height` 一个旋钮 = 前瞻长度，比赛现场调这一个数就有明显手感变化。

### 5.2 我们的改法
```c
/* MIDLine_REMAIN.c: 替换 w[row] = 1 + 0.2*row */
#define MIDLINE_LOOKAHEAD_H   (MIDLINE_MAX_HEIGHT)     /* 前瞻高度：只统计这一行以下 */
uint32_t w = (uint32_t)h * h + 1;                       /* h = MIDLINE_MAX_HEIGHT - row */
if (h > MIDLINE_LOOKAHEAD_H) continue;
```
速度快了就把 `MIDLINE_LOOKAHEAD_H` 加大（看得更远），速度慢则减小。**这个参数应该跟目标速度联动**：
```c
lookahead = clamp(MIDLINE_LOOKAHEAD_MIN + K_V * speed_ref, MIN, MAX);
```

## 6. 边线提取与补线：我们最薄的一环

### 6.1 三种表示
| | 表示 | 补线能力 |
|---|---|---|
| 我们 `Bedline_REMAIN.c:72-121` | 每侧 **一条直线** `col = k*row + b`（一次最小二乘） | **无**。十字靠"锁定直行"硬撑 |
| ZongZuanFeng `Camera.c:279-336,350-513` | **逐行窗口跟踪**（上一行边界 ±5），三态 `'T' 跳变 / 'W' 全白丢线 / 'H' 全黑` | 三种：半宽表偏移、双锚点线性插值、竖直延伸 |
| USTB `search.c:427-...`（2883 行） | **八邻域迷宫法**边界点数组 `boundary_l/r[]` + 每行 `edge_l/r[]` + **拐点表** | 4 段折线拟合曲线 `addLineCloseCurve()` + 射线求交 `getExitPoint()` |

### 6.2 ZongZuanFeng 的三态窗口跟踪（性价比最高，先抄这个）
```c
/* 概念代码，来自 Camera.c:279-336 的回读 */
for (row = 58; row >= 2; row--) {
    win = [last_edge-5, last_edge+5];
    if (窗内既无跳变也无全白)  { edge[row] = last_edge; Miss++; }       /* 'W' 丢线：沿用上一行 */
    else if (窗内全黑)          { edge[row] = last_edge; }              /* 'H' 全黑（十字/断线） */
    else                        { edge[row] = 找到的跳变点; last_edge = edge[row]; Miss = 0; }
    if (连续两个 'W')           { WhiteLine++;  /* 十字计数 */ }
    else                        { WhiteLine--; }
    if (Miss_L > 3 && Miss_R > 3 && !(双 W)) OFFLine = 1;               /* 真出界 */
}
```
关键点：**丢线不是"停止跟踪"，而是"沿用上一行"并累计 `Miss`**；`Miss` 同时是丢线判据和"出界"判据的来源。我们的 `bedline_track()` 是"连续丢 6 行就 `break`"，等于**放弃治疗**，剩下一半图像全废。

### 6.3 USTB 的补线原语（需要时再上）
```c
/* calculate.c:516-544：用 4 段直线拼一条二次曲线（无浮点），bump = 中央突起 */
uint8_t addLineCloseCurve(Point_uint8 *pts, uint16_t num, uint16_t maxNum,
                          uint8_t x1,uint8_t y1,uint8_t x2,uint8_t y2, int8_t bump)
{
    mid_x=(x2+x1)>>1; mid_y=(y2+y1)>>1;
    midl_x=(mid_x+x1)>>1; midh_x=(x2+mid_x)>>1;
    mid_x -= bump; midl_x -= bump*3/4; midh_x -= bump*4/5;   /* 中央突起 */
    num = addLine_straight(...x1,y1 → midl...);
    num = addLine_straight(...midl → mid...);
    num = addLine_straight(...mid → midh...);
    num = addLine_straight(...midh → x2,y2);
    return num;
}
```
`addLine_straight()` 就是逐行线性插值补点；`getExitPoint()`（`calculate.c:549-590`）用射线与图像边框求交，解决"补线该补到画面外哪里"。

### 6.4 结论
我们现在的"单直线拟合"在**直道和缓弯没问题**（这也是它还能跑的原因），但在**急弯/十字/环岛**全面失效，而且**没有任何补救手段**。优先级：
1. 窗口跟踪 + `Miss` 计数（替换 `bedline_track()`）——收益最大，改动最小；
2. 双侧 `Miss` 差异 → 弯道/出界判据；
3. 双锚点插值补线（十字）→ 环岛状态机 → 拐点检测。

## 7. 元素识别：判据长什么样

### 7.1 ZongZuanFeng 的圆环（4 态，最简单可用）
`Camera.c:722-764`：
- 状态 `IDLE → ENTRY → INSIDE → EXIT`，**ENTRY 立即进 INSIDE（不等确认）**，靠 EXIT 的严格条件兜底；
- `INSIDE → EXIT`：`OFFLine <= 2 && Miss < 4`；
- `EXIT` 需**连续 8 帧稳定**才清标志，且**禁止回退**（防止在环里反复切状态）。
- 入环判据（`:766-806`）：对侧 `Miss > 3` + 本侧 `Miss >= 13`（右环 15）+ `OFFLine <= 2` + 对侧 `Straight_Judge > 3.0` + 近场 59~55 行无 `'W'` + 58→26 行左边界跳变 >4 px 次数 ≥2。

### 7.2 ZongZuanFeng 的十字
`Camera.c:1057-1137`：`WhiteLine >= 8` 触发；补线时取"第一段 `'W'` 的下一行"作**近锚点**，向远端找**连续 3 行 `'T'`** 作**远锚点**，两点线性插值补中线。

### 7.3 USTB 的环（7 态，最全）
`search.c:1439-1650`（左环，右环对称）：状态 0→1 需"左侧 7 点贴边且够低 + 拐点周围边界向右上突出 + 拐点上方左贴边 + 右侧无拐点"；状态 2→3 靠"左右无拐点且右边界到左"；6→0 靠"左侧无拐点或第一贴边过低"；另有**强制退出**条件（无拐点、不贴边、都到顶，`search.c:1645`）。
额外资产：斜十字 `element_excross`（`search.c:2151-2229`）、坡道 `element_bridge`（用车体加速度 + 图像宽度差双重判据，`schedule.c:106-110` 的 `ori_gyro_x > 3500` 是**陀螺仪判坡**）、阻挡 `element_block_l/r_state`。

### 7.4 对我们的意义
我们现在只有十字（`MIDLine_REMAIN.c:219-271`）+ 斑马线（`Zebra_REMAIN.c`），**其余全缺**。建议顺序：**出界/丢线降级 → 十字补线（替掉"锁定直行"）→ 环岛 4 态 → 坡道（陀螺）→ 断路/障碍**。
注意 ZongZuanFeng 的门控是"四标志全 0 才判"（`Scan_Element`），多元素叠加会漏 → 我们写的时候用**优先级链**而不是互斥门控。

## 8. 架构：把 CPU1 用起来

ZongZuanFeng 是**双核分工**的样板（同芯片，可直接照抄划分）：

| | CPU0（感知核） | CPU1（控制核） |
|---|---|---|
| 任务 | 等帧 → 二值化 → 基线 → 边线 → 元素 → 算 `Err` → IPS200 显示 | PIT 10 ms：`PI_Update` → `Motor_Set*PWM` → `PD_Update` |
| 外设 | MT9V03X、IPS200、全部 UART、DMA | 只有 2 个 PIT |
| 中断表 | `isr_config.h`：CCU6_0_CH0/CH1→cpu0(prio 30/31)，EXTI2→**DMA**，EXTI3(VSYNC)→cpu0，DMA ch5→cpu0(60) | CCU6_1_CH0/CH1→cpu1(32/33) |
| 核间 | `code/Shared.h:23-26` 只共享 4 个裸 `volatile` 标量：`Err / StopRequest / EncLeft / EncRight` | 同 |

我们 `user/cpu1_main.c` 现在是**完完全全的空工程**（`core1_main()` 里除了 `cpu_wait_event_ready()` 什么都没有，`cpu1_main.c:46-64`），而 CPU0 上图像（约 20 ms/帧）和 5 ms 控制中断挤在一起 —— 一个 20 ms 的图像处理会把控制中断延迟最多 20 ms（虽然中断能抢占，但中断内的浮点/整型长运算会互相拖慢）。

**建议划分（改动量可控）**：
- CPU0：`Camera_Process_Once` + `Zebra_Scan` + `Find_Badpoint` + `Find_Bedline` + `Find_MIDLine` + 显示；
- CPU1：`Control_Tick`（5 ms PIT）+ `Servo_Set_Turn` + 编码器读取；
- 共享：`volatile int16 mid_error`、`volatile uint8 stop_request`、`volatile int16 speed_l/r`（跟 ZongZuanFeng 一样，四个标量足够）。
> 注意：`mid_error` 是单 16 位量，TC264 上对齐的 16 位读写是原子的，不需要临界区；但**多字段的结构体（如 `midline_info`）跨核共享就必须双缓冲或序号锁**。

### 8.1 参数在线整定（三个仓库都做得很差，是我们能领先的地方）
- USTB：参数走 **AT24C EEPROM 分块存储**（7 档 × 256 B，`keyboard.h:23/36` + `keyboard.c:9-17` 的 `AT24C_R32(addr)` 自动加块偏移），但**在线调参 UI 被删了**（`main.c:159-162` 注释"键盘调参 不开源"）。
- ZongZuanFeng：**完全没有**（5 键驱动在，没接调参；无线 UART handler 挂空）。
- 我们：全是 `#define`，但库里 **`seekfree_assistant` + `wireless_uart` + `virtual_oscilloscope` 全在**（`libraries/zf_components/`、`libraries/zf_device/`），本来就能做"上位机改参数 + 波形"。

**最小可用方案**：一组 `ramp_kp/kd/up_step/down_step/lookahead` 放进 `struct ctrl_param`，上电从 flash 读、无线 UART 收到帧就改、按键长按保存。这比再调一个 PID 参数有用得多。


### 8.2 控制频率分层：速度环和航向环不该同频

我们现在的做法是两个环都在同一个 5 ms PIT 里跑（`user/isr.c:47` → `Control_Tick()` → `Control_REMAIN.c:326` 调 `Servo_Set_Turn`）。但**航向信息的更新率等于图像帧率**（约 50 fps，20 ms），把舵机放在 5 ms 里跑，意味着**四次里有三次在重复计算同一个偏差**。

两个仓库给出了同向的证据：

| 仓库 | 速度环 | 航向/外环 | 说明 |
|:--|:--|:--|:--|
| `losehu/smartcar-C` | TIM6 中断 **1 ms** | **图像帧率事件驱动**（`img_flag` 置位才跑 PID） | 作者把两个环彻底解耦 |
| `RT1064_Smartcar` | 电机 LADRC **1 kHz** | ESKF + LocalPlanner **200 Hz** | 内环 5 倍于外环 |

**业界惯例是内环频率 ≥ 外环 5 倍**，理由是外环输出的"目标"在内环里被高频跟踪，外环自身不需要快。我们反过来把最贵的环（浮点 PID + 出弯保持状态机）塞进 5 ms，把最便宜的（编码器差分测速）也塞进 5 ms，两头都不对。

**改法（两行级）**：在 `Control_REMAIN.c:326` 前加一个新帧门控——

```c
static uint8 last_frame = 0;
if(midline_info.frame_id != last_frame){       /* 只有新帧才更新航向 */
    last_frame = midline_info.frame_id;
    Servo_Set_Turn(error);
}
```

省下来的 CPU 直接给图像处理，或者把 `Control_Tick` 里速度环的周期继续保持 5 ms（速度环用编码器，确实可以快）。

> 这也是 03 里"三个半行到两行的低成本改动"的第一条。
