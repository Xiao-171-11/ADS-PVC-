## A1 · 逆透视查表接入（P0）


> **双源交叉验证**：`losehu/smartcar-C` 与 `RUBO-UDIPM` 是两个互不相关的作者，却给出了**结构完全一致**的实现——都是 `100×114` 的 `uint8_t*` 指针表（≈45.6 KB）、都是初始化时算一次、越界像素统一指向同一个白色常量、运行时只做一次解引用。这不是巧合，而是 MCU 上做逆透视的唯一可行姿势（每帧跑 11400 次浮点乘加根本来不及）。另外 losehu 标定出 `RoadWide0 = 45`，即 **1 px = 1 cm**，说明 100×114 的输出网格在标准 PVC 赛道上分辨率刚好够。

### 现状

`code/Camera_REMAIN.c:126-137` `Camera_Binarize()` 先 `memcpy` 整帧 22560 字节，再逐像素写 0/255 —— 在**透视图像**上做。`code/Bedline_REMAIN.c:72-121` `bedline_fit()` 对全部边线点做一次最小二乘 → `col = k*row + b`。

透视投影下，平行车道线在图像里是收敛的，弯道是二次曲线拟合出来的双曲线。直线拟合的残差随曲率单调增大 → **弯越急，边线越偏，且方向恒定偏向内侧**。这不是调参能救的。

### 目标

把"原始 MT9V03X 188×120"变成"去畸变+逆透视后的 100×114 俯视图"，其中行号 ≈ 纵向距离、列号 ≈ 横向距离，直线重新是直线、圆环重新是圆。

### 具体改法

**第 1 步：生成标定参数（一次性，离线）**

1. 打印 `.research_refs\RUBO-UDIPM\RUBO-UDIPM-main\棋盘标定图.pdf`，平铺在赛道上摄像头视野内。
2. 用本车的 MT9V03X 拍一张（临时用 `zf_device_wifi_uart` 把 `mt9v03x_image` 整帧发出，或先存到 SD 卡）。
3. 打开 `RUBO_UDIPM.exe`：先"去畸变标定"（选棋盘图，它会输出 `cameraMatrix` / `distCoeffs` / `move_xy`），再"逆透视"（在去畸变图上点四个赛道矩形角点，输出 `change_un_Mat`）。
4. 导出"去畸变+逆透视下位机"代码。

**第 3 步：新增 `code/IPM_REMAIN.c`**

用 `uint16_t` 偏移表代替指针表（`100×114×4=45.6KB` → `100×114×2=22.8KB`）：

```c
#include "IPM_REMAIN.h"

#define SRC_ROW     (MT9V03X_H)     // 120
#define SRC_COL     (MT9V03X_W)     // 188
#define TEMP_ROW    (120)           // 去畸变后中间图
#define TEMP_COL    (180)
#define IPM_INVALID (0xFFFF)

// ===== 以下六组参数由 RUBO_UDIPM.exe 导出后替换 =====
static const double cameraMatrix[3][3] = {
    {296.482019,   0.000000, 152.664982},
    {  0.000000, 286.375269, 104.540031},
    {  0.000000,   0.000000,   1.000000}
};
static const double distCoeffs[5] = {-0.459946, 0.283675, 0.002304, 0.002566, -0.109265};
static const int    move_xy[2]    = {10, 0};
static const double change_un_Mat[3][3] = {
    { 2.936703,  0.314530, -60.814898},
    {-0.263326,  2.308885, -108.340381},
    {-0.000835,  0.000896,    0.969316}
};
// ===================================================

static uint16_t ipm_map[IPM_ROW][IPM_COL];      // 输出坐标 -> 源坐标一维偏移
uint8_t ipm_image[IPM_ROW][IPM_COL];

// 中间图坐标 (x,y) -> 原始畸变图坐标
static void ipm_undistort(int x, int y, int local[2])
{
    double fx = cameraMatrix[0][0], fy = cameraMatrix[1][1];
    double ux = cameraMatrix[0][2], uy = cameraMatrix[1][2];
    double k1 = distCoeffs[0], k2 = distCoeffs[1], k3 = distCoeffs[4];
    double p1 = distCoeffs[2], p2 = distCoeffs[3];

    double xc = (x - ux) / fx;
    double yc = (y - uy) / fy;
    double r2 = xc * xc + yc * yc;
    double ra = 1.0 + k1 * r2 + k2 * r2 * r2 + k3 * r2 * r2 * r2;
    double tx = 2.0 * p1 * xc * yc + p2 * (r2 + 2.0 * xc * xc);
    double ty = p1 * (r2 + 2.0 * yc * yc) + 2.0 * p2 * xc * yc;

    double xd = xc * ra + tx;
    double yd = yc * ra + ty;
    xd = xd * fx + ux;
    yd = yd * fy + uy;

    if (yd >= 0.0 && yd < SRC_ROW && xd >= 0.0 && xd < SRC_COL) {
        local[0] = (int)yd;
        local[1] = (int)xd;
    } else {
        local[0] = -1;
        local[1] = -1;
    }
}

// 输出坐标 (x,y) -> 中间图坐标（单应性）
static void ipm_homography(int x, int y, int local[2])
{
    double w = change_un_Mat[2][0] * x + change_un_Mat[2][1] * y + change_un_Mat[2][2];
    if (w > -1e-6 && w < 1e-6) { local[0] = -1; local[1] = -1; return; }

    int lx = (int)((change_un_Mat[0][0] * x + change_un_Mat[0][1] * y + change_un_Mat[0][2]) / w);
    int ly = (int)((change_un_Mat[1][0] * x + change_un_Mat[1][1] * y + change_un_Mat[1][2]) / w);

    if (lx >= 0 && ly >= 0 && lx < TEMP_COL && ly < TEMP_ROW) {
        local[0] = ly; local[1] = lx;
    } else {
        local[0] = -1; local[1] = -1;
    }
}

// 只在初始化时跑一次：100*114 = 11400 次浮点运算
void IPM_Init(void)
{
    for (int i = 0; i < IPM_ROW; i++) {
        for (int j = 0; j < IPM_COL; j++) {
            ipm_map[i][j] = IPM_INVALID;

            int mid[2] = {-1, -1};
            ipm_homography(j, i, mid);
            if (mid[0] < 0) continue;

            int src[2] = {-1, -1};
            ipm_undistort(mid[1] - move_xy[0], mid[0] - move_xy[1], src);
            if (src[0] < 0) continue;

            ipm_map[i][j] = (uint16_t)(src[0] * SRC_COL + src[1]);
        }
    }
}

// 每帧：11400 次 table lookup + 11400 次字节拷贝，无浮点
uint8_t IPM_Update(void)
{
    if (mt9v03x_finish_flag == 0) return 0;
    mt9v03x_finish_flag = 0;

    const uint8_t *src = (const uint8_t *)mt9v03x_image;

    for (int i = 0; i < IPM_ROW; i++) {
        uint16_t *map = ipm_map[i];
        uint8_t  *dst = ipm_image[i];
        for (int j = 0; j < IPM_COL; j++) {
            uint16_t off = map[j];
            dst[j] = (off == IPM_INVALID) ? IPM_FILL_VALUE : src[off];
        }
    }
    return 1;
}

uint8_t IPM_Get(uint16_t row, uint16_t col)
{
    if (row > IPM_ROW_MAX) row = IPM_ROW_MAX;
    if (col > IPM_COL_MAX) col = IPM_COL_MAX;
    return ipm_image[row][col];
}
```

### 验证方法

1. **上电前**：把 `ipm_map[][]` 中 `IPM_INVALID` 的比例打印出来。经验值 **20%~40%** 正常（俯视图四个角是视野外）。若 >60%，说明四点选错了；若 =0%，说明单应矩阵方向反了。
2. **静态验证**：车放在直道上，`ipm_image` 显示到 TFT180，两条边线应**接近竖直平行**。若仍收敛，逆透视参数错。
3. **动态验证**：手推车走 90° 弯，边线应保持与车体大致平行直到出视野，而不是像现在这样"提前弯折"。
4. **回归对比**：同一段赛道，记录改造前后 `midline_info.error` 的波形（无线发回上位机），弯道段误差幅值应显著下降。

## A2 · 补线结果回写边线数组（P0）

### 现状

`code/Bedline_REMAIN.c:133-195` `bedline_track()` 在 `±BEDLINE_SEARCH_GAP(6)` 窗口内先外后内找色变点，连续丢 `BEDLINE_MAX_LOST(6)` 行就**终止**（`break`）。之后 `bedline_fit()` 用"已经终止的点集"拟合——**丢线的那几行完全没有边线数据**，拟合线自然向内偏。

参考仓库里三种处理方式，只有一种是对的：

| 做法 | 代表 | 结果 |
|:--|:--|:--|
| 丢线直接 `break`，用剩余点拟合 | **本工程** | 边线短一截，拟合斜率被前段主导 |
| `'W'` 全白时沿用上一行 | ZongZuanFeng `Camera.c:350-513` | 边线不断，但假数据混入拟合 |
| **把补出来的假线画回二值图，再重跑一遍提取** | wuyou33 `get_image.c:70-81`+`131-169` | 假线与真线走同一套逻辑，中线和断线行自动一致 |
| 补线只写图不写数组 | xiayu `image.c:654-663` | **对控制完全无效**（反面教材） |

### 目标

丢线时用"已确认段的斜率"外推补全，且**补全结果进入与真实边线相同的下游处理**，不允许出现"补了但没用上"或"补了但和真线走不同代码路径"。

### 具体改法

在 `code/Bedline_REMAIN.c` 里把 `bedline_track()` 改成两段式：

```c
// 新增：在 track 内部维护一个 valid 标志
static uint8_t bedline_valid[BEDLINE_MAX_POINTS];   // 1=真实点 0=外推点
static uint8_t bedline_lost_cnt;

// 轨迹跟踪结束、进入 fit 之前，统一做一次补全
static void bedline_extrapolate(void)
{
    uint8_t last_valid = 0xFF;

    for (uint8_t i = 0; i < bedline_point_num; i++) {
        if (bedline_valid[i]) { last_valid = i; continue; }
        if (last_valid == 0xFF) continue;           // 起始就丢，无法外推，留空
    }

    // 用最后 K 个真实点算斜率（K=8 足够，太多会被远处噪声污染）
    const uint8_t K = 8;
    if (last_valid < (uint8_t)(K - 1)) return;

    float sum_r = 0, sum_c = 0, sum_rr = 0, sum_rc = 0;
    for (uint8_t i = last_valid - K + 1; i <= last_valid; i++) {
        float r = bedline_points[i].row, c = bedline_points[i].col;
        sum_r += r; sum_c += c; sum_rr += r * r; sum_rc += r * c;
    }
    float den = K * sum_rr - sum_r * sum_r;
    if (fabsf(den) < 1e-3f) return;                 // 竖直段，斜率无穷，放弃外推
    float k = (K * sum_rc - sum_r * sum_c) / den;
    float b = (sum_c - k * sum_r) / K;

    // 外推：从 last_valid+1 到末尾
    for (uint8_t i = last_valid + 1; i < bedline_point_num; i++) {
        float c = k * bedline_points[i].row + b;
        if (c < 0) c = 0;
        if (c > IPM_COL_MAX) c = IPM_COL_MAX;
        bedline_points[i].col = (uint8_t)(c + 0.5f);
        bedline_valid[i] = 0;                       // 标记为外推
    }
}
```

关键：`bedline_points[i].row` 必须**已经填好**（当前实现是 `break` 后数组尾部就是空的）。所以 `bedline_track()` 里那个 `break` 要改成 `continue`——丢线不停，只把 `valid` 清 0，让行号连续：

```c
// code/Bedline_REMAIN.c: 原 break 处
if (lost >= BEDLINE_MAX_LOST) {
    // 原：break;
    bedline_valid[i] = 0;      // 本行外推
    continue;
}
bedline_valid[i] = 1;
```

然后 `bedline_fit()` 增加一个"是否允许外推点参与拟合"的开关——**推荐：真实点算斜率，外推点也一起进最小二乘**（因为斜率就是它们自己推出来的，自洽，不会引入新的偏差方向）：

```c
// code/Bedline_REMAIN.c:72-121 bedline_fit()
// 末尾增加置信度输出，供 B3/C1 使用
bedline_confidence = (float)real_cnt / (float)bedline_point_num;   // 0~1
```

`bedline_confidence` 是后续"丢线降级"（空白清单 #2）的唯一输入，比现在的二值判断可靠得多。

### 验证方法

1. 在 `MIDLine_REMAIN.c` 里把 `bedline_valid[]` 着色显示到 TFT180（真点绿、外推点红），手推车过弯，**红色段不应超过总长度的 40%**。
2. `bedline_confidence` 打到屏上：直道应 >0.95，弯道 0.7~0.9，丢线 <0.5。若直道也 <0.9，说明 `BEDLINE_MAX_LOST(6)` 太紧。
3. 回归：记录 `bedline_fit` 的斜率 `k` 波形，改造后弯道段应更平滑（不再因为点集截断而跳变）。

### 风险

- **外推点污染拟合**：如果最后 8 点本身就含外推点，斜率会自我强化。所以外推前必须确认 `last_valid` 是真实点，且 `K` 个点全为真——代码里 `last_valid - K + 1` 到 `last_valid` 这段要额外校验 `bedline_valid[]`。
- 竖直段 `den≈0` 时直接放弃外推（代码已处理），此时输出 `bedline_confidence` 会偏低，是正确行为。

## A3 · 八邻域双栈爬线取代逐行扫线（P2，可选）

> 这一项是"要不要换掉现有的逐行扫线"的决策项，**不是必须做**。A1/A2 做完之后再评估。

### 现状

`code/Bedline_REMAIN.c:133-195` `bedline_track()`：从基点开始**逐行向上**，在 `±BEDLINE_SEARCH_GAP(6)` 内先外后内找色变点；连续丢 `BEDLINE_MAX_LOST(6)` 行就 `break`；最多收 `BEDLINE_MAX_POINTS(60)` 个点。

特点：**行数固定、每行最多一个点**。所以：
- 遇到"某一行有两条候选边"（岔路口、环岛入口）时，只能选一个 → 选错就整条线跑偏；
- 竖直方向的边（宽度骤变处）采不到；
- 丢掉的那几行**永远补不回来**，只能靠 A2 的外推。

### 目标

换成 `losehu/smartcar-C` 的**八邻域双栈爬线**（`image_deal.c:1311-1534`）：从种子点出发沿边线"爬"，左右各维护一个点栈，允许在同一行采多个点。

优势：能处理竖直边、岔路口、环岛入口这些"一行两候选"的情况；劣势：实现复杂度高一个量级，且**必须一次做对**（`search_line` 中途 `return` 会留半帧脏状态，它自己就有 6 个中途 return）。

### 参考实现的三个关键手法

1. **左右同步不是靠对称相位，是靠计数配平**：`up_left_num / up_right_num` 两个计数器 + `max_py/min_py` 门控 + `down_flag` 二次向下补。比 `xiayu` 那套"左在头右在尾"的非对称相位稳，但也更难抄对。
2. **落行取极值**：左线取同行**最大** `x`、右线取同行**最小** `x`（不是取中点，也不是取第一个命中）。
3. **丢线判据 = 贴边 10 px 内**，而不是"找不到色变点"。这比我们的 `lost > 6` 更有物理意义。

### 决策建议

| 情况 | 建议 |
|:--|:--|
| A2 的 `bedline_extrapolate()` 已经能把 90% 的弯道补稳 | **不做 A3**。收益有限，风险很大 |
| 主要失分在环岛入口 / 岔路口 / 竖直墙 | 做 A3，并且**先只替换左线**，右线保持原样跑对照 |
| 想做但没时间 | 抄它的**落行取极值**（10 行改动）和**丢线判据改成贴边距离**（5 行），不抄整套 |

### 风险

- 八邻域是全工程最难调的一段代码。`RUBO-UDIPM` 那种"指针表 + 直接解引用"的写法之所以好，是因为它把复杂度锁在初始化里；而八邻域把复杂度放在了**每帧的热路径**上。
- 一定要**同时保留旧实现**，用一个宏 `TRACK_USE_8NEIGHBOR 0/1` 切换，否则出问题没法回退。
- 栈容量要在最坏情况（全黑图、全白图）下测过，`losehu` 自己就有 `Ysite==stack_top`（拿行号比栈深）这种 bug。

## B1 · 四象限非对称限幅（P1）

### 现状

`code/Control_REMAIN.c:102-121`：

```c
// 位置式 PID：out = kp*e + ki*Σe + kd*(e-last_e)
// 对称限幅 ±500
```

`+500` 和 `−500` 是对称的。但电机的物理约束不对称：**加速受电流/电池内阻限制（不能猛），减速（反向制动）几乎无限制**。对称限幅的结果是"想加速时被电池拖住，该减速时又刹不住"。

### 目标

抄 USTB_Swan `control.c:312-328` 的四象限限幅：上限随目标速度自缩放。

### 具体改法

```c
// code/Control_REMAIN.c
#define PID_OUT_MAX          (500)      // 原有对称上限（保留给方向环）
#define PID_BRAKE_GAIN       (13)       // USTB_Swan 用的是 13，含义：超速时允许的负向余量倍数

static void control_pid_clamp(pid_struct *pid, float actual, float target)
{
    float out = pid->out;

    if (actual > target) {
        // 超速：负向放开到目标速度的 13 倍（可以有足够的制动余量）
        float neg_limit = -(target * PID_BRAKE_GAIN);
        if (neg_limit > -PID_OUT_MAX) neg_limit = -PID_OUT_MAX;   // 不要比对称上限还松
        if (out < neg_limit) out = neg_limit;
        if (out > PID_OUT_MAX) out = PID_OUT_MAX;
    } else {
        // 未达速：正向只给对称上限，负向收紧（避免反向拖拽）
        if (out < -PID_OUT_MAX / 2.0f) out = -PID_OUT_MAX / 2.0f;
        if (out > PID_OUT_MAX) out = PID_OUT_MAX;
    }

    pid->out = out;
}
```

**注意 USTB_Swan 的原式是 `CLAMP(pwm, -9999, target*13)`**——它的 `target` 本身就是 0~9999 量级的占空比，所以 `target*13` 是正数上限。本工程的 `target` 是速度单位（`CONTROL_BASE_SPEED=75`），语义不同，**不能照抄系数**。上面的写法是"同一个意图在本工程量纲下的正确版本"：超速时放宽负向、未达速时放宽正向。

若要用更贴近原式的写法：

```c
// 直接对占空比做限幅（绕开 PID 输出域），更接近 USTB_Swan 原意
int32_t duty = (int32_t)(gain * speed + offset + pid->out);
int32_t duty_max = MOTOR_DUTY_MAX;                        // 8000
int32_t duty_brake = (int32_t)(target_duty * 13 / 10);    // 1.3 倍目标，比 13 温和
if (speed > target) {
    if (duty < -duty_brake) duty = -duty_brake;
} else {
    if (duty > duty_max) duty = duty_max;
    if (duty < -duty_max) duty = -duty_max;
}
```

### 验证方法

1. 台阶响应：目标速度从 22.5 跳到 75，记录 `duty` 与编码器速度波形。改造后上升沿应更陡（正向不被限），超调后的负向制动应更深（回落更快）。
2. 弯道：进弯减速时，若出现"减速不足 → 冲出"，说明 `duty_brake` 给得太大，往 1.0 收。

### 风险

- 负向余量过大 → 反向制动过猛 → 后轮抱死打滑。**先在 `duty_brake = target_duty` 上试，确认不滑再放大。**

## B2 · 速度斜坡（1:25 非对称）（P1）

### 现状

`code/Control_REMAIN.c` 里 `CONTROL_BASE_SPEED=75`、`弯道减速 slow=clamp(1-0.008*|error|, 0.45, 1)` —— 目标是**每拍直接跳到**这个值，从 75 掉到 33.75 是一步完成的。

对比：
- USTB_Swan `schedule.c:283-302`：`up_step=1`、`down_step=25`，**加速:减速 = 1:25**。
- 17th-SmartCar `Motor.c:765+`：电容电压分段限速（4.3/3.3/2.5/1.8 → 110/100/70/25），只做稳态上限，不做斜坡。
- wuyou33：纯阶跃（作者自己写的连续版被注释了）。

### 目标

加速要慢（防打滑、防电流冲击），减速要快（该收就收）。速率比 1:25 是 USTB_Swan 在真实赛道上调出来的经验值。

### 具体改法

```c
// code/Control_REMAIN.c
#define SPEED_RAMP_UP_STEP      (0.6f)      // 每 5ms 允许上升的速度增量（=75*0.008，约 0.12s 从 0 到 75）
#define SPEED_RAMP_DN_STEP      (15.0f)     // 每 5ms 允许下降的增量（=75*0.2，约 25ms 收完）
                                            // 比值 0.6:15 ≈ 1:25

static float speed_ref_ramp = 0.0f;

// 在控制 tick 开头调用：target_speed 是本拍算出来的期望速度
static float speed_ramp(float target_speed)
{
    if (target_speed <= 0.0f) { speed_ref_ramp = 0.0f; return 0.0f; }

    float diff = target_speed - speed_ref_ramp;
    if (diff > SPEED_RAMP_UP_STEP) {
        speed_ref_ramp += SPEED_RAMP_UP_STEP;
    } else if (diff < -SPEED_RAMP_DN_STEP) {
        speed_ref_ramp -= SPEED_RAMP_DN_STEP;
    } else {
        speed_ref_ramp = target_speed;          // 已到，贴合（避免永远差一点）
    }

    if (speed_ref_ramp < 0.0f) speed_ref_ramp = 0.0f;
    return speed_ref_ramp;
}
```

**重要**：`speed_ref_ramp` 必须是 `static` 且**只在控制 tick 里推进**，不能放在帧驱动的主循环——否则帧率抖动会让斜坡速率不稳定（这正是 wuyou33 方向环 D 项失效的同一个病根）。

### 验证方法

1. 把 `speed_ref_ramp` 与编码器实测速度同时打到屏上，两者应贴合，且 `speed_ref_ramp` 无阶跃。
2. 急弯测试：改造前进弯可能甩尾，改造后应明显改善。
3. 起步测试：从静止加速到 `CONTROL_BASE_SPEED`，看电流/占空比峰值是否下降。

### 风险

- 斜坡太慢 → 直道末端速度上不去。`SPEED_RAMP_UP_STEP=0.6` 是 0.12s 满加速，若赛道全是短直道，需改成按"距下一个弯的距离"规划（参考 RT1064 的 `LocalPlanner`）。
- 停车分支（`CONTROL_LOST_STOP_TICKS`）必须直接清零 `speed_ref_ramp`，不能走斜坡——**安全优先于平顺**。

## B3 · 中线改 `line²+1` 加权 + `turn_height` 旋钮（P1）

### 现状

`code/MIDLine_REMAIN.c:65` `w[row] = 1 + 0.2*row`（线性，越靠车头越大）→ `:208-209` 互补滤波 `center = 0.2*last + 0.8*now`。

线性权重的问题：**前瞻量的等效值不明确**。你想"多往前看一点"，只能全局改系数，结果是近处和远处同时变。USTB_Swan 的做法把这件事变成一个物理量。

### 目标

抄 `calculate.c:760-778`：

```c
static float get_weight(int line, int height)
{
    if (line <= height) return line * line + 1.0f;
    else                return (line * line) / (line - height) + 1.0f;
}
```

`height` 就是 `turn_height`（前瞻长度，单位=行）。`line` 是行号（**从车头算起的距离**）。性质：
- `line < height`：二次增长，远端权重最大。
- `line = height`：分母趋 0，权重爆炸 → 相当于"前瞻点"。
- 实用上不会取到等号（`calcTurnLine()` 里有 `相邻差<2 跳过` 的保护）。

### 具体改法

```c
// code/MIDLine_REMAIN.c
#define MIDLINE_TURN_HEIGHT     (55)        // 可调：行（IPM 图共 100 行；55 ≈ 视野中段）
                                            // 调大 = 看得更远、更晚打角；调小 = 更贴车头

static float midline_weight[IPM_ROW];       // 初始化时算一次

void MIDLine_Weight_Init(void)
{
    const int H = MIDLINE_TURN_HEIGHT;
    for (int r = 0; r < IPM_ROW; r++) {
        int line = IPM_ROW_MAX - r;         // 行号小的在远处，line = 距车头的行数
        if (line <= 0)       midline_weight[r] = 1.0f;
        else if (line <= H)  midline_weight[r] = (float)(line * line) + 1.0f;
        else                 midline_weight[r] = (float)(line * line) / (float)(line - H) + 1.0f;
    }
}

// Find_MIDLine() 内的加权平均改写
static void midline_weighted_average(void)
{
    float sum_w = 0.0f, sum_wc = 0.0f;

    for (int r = 0; r < IPM_ROW; r++) {
        if (!midline_row_valid[r]) continue;
        float w = midline_weight[r];
        sum_w  += w;
        sum_wc += w * (float)mid_line_row[r];
    }

    if (sum_w < 1e-3f) {                    // ★ 关键：不能让它除零
        midline_confidence = 0.0f;
        return;                             // 保持上一帧 center，不更新
    }
    midline_confidence = sum_w / MIDLINE_WEIGHT_FULL;   // 归一化到 0~1

    float now = sum_wc / sum_w;
    mid_line_center = 0.2f * mid_line_center_last + 0.8f * now;
    mid_line_center_last = mid_line_center;
}
```

**`sum_w < 1e-3f` 那个分支是整段代码最重要的三行。** wuyou33 就是因为 `over>=57` 时 `WeightSum=0` 而让偏差保持 0，然后算出 `temp = −40` → **满舵左打**（`get_image.c` 的 `deviationestimate()`）。丢线时必须"保持上一帧"或"按置信度衰减"，绝不能落到默认值。

### 验证方法

1. 只改 `MIDLINE_TURN_HEIGHT` 这一个数（50/55/60/65），跑同一条赛道记录圈速与最大偏差。应该存在一个明显最优点——这就是这个设计的价值。
2. 直接把 `MIDLINE_TURN_HEIGHT` 接到无线命令上在线改（见 C2），**不用重编译**。
3. `midline_confidence` 打到屏上：直道近 1.0，弯道 0.6~0.9。

### 风险

- `line = height` 附近权重爆炸 → 单个远端噪声点能主导平均值。对策：权重上限截断 `if (w > 200.0f) w = 200.0f;`。
- 改动后 `error` 幅值范围会变（权重归一化后仍是像素单位，但分布不同），`Control_REMAIN.h:88-91` 的 `ratio=0.004*error` 封顶 0.5 与 `slow=clamp(1-0.008*|error|)` 都要重新标定。

### 另一个独立实现：losehu 的三段权重 + 3 点 FIR

`losehu/smartcar-C` 的中线权重（`image_deal.c:1538-1586`）是**三段常数**，比 `line²+1` 更粗暴但更容易调：

```c
line_wight[i] : 第 0-19 行 = 1      // 最近处：白线粗、噪声大，不信
                第 20-49 行 = 10    // 中段：最可信
                第 50-99 行 = 1     // 最远处：已补线，不信
point_center0 = sum / cnt * 2              // 归一化到"半路宽 = 100"
point_center  = 0.6*now + 0.3*h1 + 0.1*h2  // 3 点 FIR（不是互补滤波）
```

它的哲学与 USTB 的 `line²+1`（远端权重最大）**正好相反**：USTB 赌"远处才是有用的前瞻"，losehu 赌"远处已经不可信"。**没有对错，取决于你的补线质量**：
- 补线可靠 → 用 USTB 的远端加权（我们的 A2 做完后应该走这条）；
- 补线不可靠 → 用 losehu 的中段加权（A2 没做完之前更安全）。

这也解释了为什么我们把 B3 排在 A1、A2 之后：**权重方案的选择依赖补线质量**。

### 顺带一个两行改动：`(99 - Topline)` 加权双段 Kp

`losehu` 的舵机式（`pid.c:240-241`）：

```c
servo = kp1 * e + kp2 * (99 - Topline) * e / 1000 + ki * (e+e1+e2) + kd * (e-e1);
//                  ^^^^^^^^^^^^^^^^ 视野越短，增益越保守
```

`Topline` = 本帧边线最高有效行。远端被截（视野变短）时，图像信息量下降，**主动降低增益**。我们现在的双段 Kp 是按 `|error|` 切的，和视野长度无关——加这一项只需两行，但能在补线失败/远端丢线时避免满舵。

## B4 · 陀螺仪接入 + 角速度阻尼（P1，性价比最高的一项）

> 这一项是写文档过程中才发现的：**代码里 99% 的活儿已经干完了，只差一行初始化。**

### 现状

`user/isr.c:87-95` 已经写好了完整的陀螺仪中断通路：

```c
IFX_INTERRUPT(exti_ch0_ch4_isr, 0, EXTI_CH0_CH4_INT_PRIO)
{
    interrupt_global_enable(0);
    if(exti_flag_get(ERU_CH0_REQ0_P15_4))
    {
        exti_flag_clear(ERU_CH0_REQ0_P15_4);
        imu660rc_callback();          // ← 这个函数体里是 imu660rc_get_quarternion()
    }
    ...
```

而 `libraries/zf_device/zf_device_imu660rc.c:392-396` 的 `imu660rc_callback()` **不是空桩**，它调用 `imu660rc_get_quarternion()`；配合头文件里的

```c
#define IMU660RC_QUARTERNION_GET_GYRO   ( 1 )   // 1：读取四元数时自动读取角速度
```

——也就是说，**只要 `imu660rc_init()` 被调用，`imu660rc_gyro_x/y/z` 这三个 `int16` 全局量就会自动按设定频率刷新**，一行中断代码都不用自己写。

但全工程搜不到任何 `imu660rc_init()` 或 `exti_init()` 调用，所以 EXTI 通道从未使能，这条中断永远不会触发。硬件上 `推荐IO分配.txt` 已经把 SPI0（P20_11/P20_14/P20_12/P20_13）留给 ICM20602，EXTI 引脚 `P15_4` 也空着。

**结论：这是当前工程里"投入一，产出十"的一项。**

### 目标

方向环从"图像 P + D"变成 **P + D + 陀螺仪阻尼**，等价于 USTB_Swan 的 `servoPID.output -= gyro_d` 和 17th 的纯 PD + 前馈。作用：

- 直道高速不摆（车体角速度被实时抵消，不依赖图像抖动采集）；
- 入弯不冲过头（图像滞后由角速度提前补偿）；
- 出弯不画龙（可以适当降低 `SERVO_KD`，减少图像噪声被放大）。

### 具体改法

**第 1 步：初始化（一行）**

`code/SATA_MAIN.c` 的 `SATA_Init()` 里，`Camera_LCD_Init();` 之后加：

```c
if(imu660rc_init(IMU660RC_QUARTERNION_480HZ))      // 0-成功 1-失败
{
    tft180_show_string(0, 16, "IMU ERR");          // 屏幕已有，直接复用报错位置
}
```

480 Hz 是最高档，远高于我们 5 ms（200 Hz）的读取节拍，够用。**不要用 `IMU660RC_QUARTERNION_DISABLE`**——那样 `imu660rc_get_quarternion()` 不会再顺手读角速度。

**第 2 步：把它变成"和单位无关"的量**

新建 `code/Imu_REMAIN.c/.h`（或直接塞进 `Control_REMAIN.c`，看你想不想多一个模块）：

```c
#include "zf_common_headfile.h"
#include "Imu_REMAIN.h"

static float imu_gz_f = 0.0f;          /* 低通后的角速度 */

/* 在 5 ms 控制中断里、算舵机之前调用一次 */
float Imu_Get_Gz(void)
{
    float gz = (float)imu660rc_gyro_z;                 /* 原始 LSB，int16 */

    /* 一阶低通：截止频率约 30 Hz，滤掉车体高频振动 */
    imu_gz_f = (IMU_GZ_FILTER * gz) + ((1.0f - IMU_GZ_FILTER) * imu_gz_f);

    if((imu_gz_f > -IMU_GZ_DEADZONE) && (imu_gz_f < IMU_GZ_DEADZONE))
    {
        return 0.0f;                                   /* 直道死区，防止静止噪声一直顶舵机 */
    }
    return imu_gz_f;
}
```

`code/Imu_REMAIN.h`：

```c
#ifndef _imu_remain_h_
#define _imu_remain_h_

#include "zf_common_typedef.h"

#define IMU_GZ_FILTER       (0.35f)    /* 低通系数，越小越平滑但越滞后 */
#define IMU_GZ_DEADZONE     (150.0f)   /* 单位是原始 LSB，必须上车实测后改 */
#define IMU_GZ_K            (0.010f)   /* 阻尼系数，唯一需要调的参数 */
#define IMU_GZ_MAX          (35.0f)    /* 阻尼量上限，单位同舵机 out（占空比计数） */

float Imu_Get_Gz(void);

#endif
```

⚠️ **`IMU_GZ_DEADZONE` 的单位不要猜**：`imu660rc_gyro_z` 是原始 LSB，量程与换算关系看 `imu660rc_transition_factor[2]`。实测办法——把车静止放在桌上，用 `tft180_show_int(0, 32, imu660rc_gyro_z, 6)` 打印 30 秒，取峰值的 1.5 倍作死区；然后手转车头 90°/s，看读数是多少，就能反推 LSB 与 °/s 的比例。

**第 3 步：接进舵机输出**

`code/Servo_REMAIN.c` 的 `Servo_Set_Turn()`，在 `out = p_out + (SERVO_KD * (error - servo_last_error));`（`:110`）**之后**、出弯保持逻辑（`:113` 的 `#if SERVO_EXIT_HOLD_EN`）**之前**插入：

```c
    /* 陀螺仪阻尼：与 PID 完全独立的通路，不做积分、不进 PID 状态机 */
#if (1 == SERVO_GYRO_DAMP_EN)
    {
        float gz = Imu_Get_Gz();                       /* 已含低通与死区 */
        float gyro_d = IMU_GZ_K * gz;

        if(gyro_d >  IMU_GZ_MAX) gyro_d =  IMU_GZ_MAX;
        if(gyro_d < -IMU_GZ_MAX) gyro_d = -IMU_GZ_MAX;

        out += gyro_d;
    }
#endif
```

**符号约定（写错了车会自己摆起来，一定要先验）**：本工程 `out` 增大 → `duty = Servo_MID + SERVO_TRIM - out` 减小 → 舵机向右打（`Servo_REMAIN.c:197`，占空比增大向左）。所以"车头正在向左转（`gyro_z` 为正）"时，阻尼应该往右打 → `out` 增大 → **`out += K*gz`**。

上车验证方法（10 秒就能判）：**用手把车头快速向左摆一下**。正确的表现是舵机轮往右"顶"一下后迅速回中；如果舵机反而顺势往左推，说明符号反了，把 `out += gyro_d` 改成 `out -= gyro_d`。

出弯保持（`SERVO_EXIT_HOLD_EN`）保持**不变**：它在 `:183-194` 会把 `out` 整个替换成 `servo_hold_out`，也就是说出弯保持期间陀螺阻尼被自然屏蔽——这正是想要的（保持阶段要的是"维持旧打角"，不是"被角速度拉走"）。

### 一个必须同步的决定

接上陀螺后，**`SERVO_KD` 应该往下调**（建议从 2.0 → 1.0~1.2）。因为原来 `SERVO_KD` 在替陀螺干活：它用"偏差的变化率"近似角速度，但偏差变化率既含车体转动也含图像噪声，所以它一直被噪声限制在很低的值。有了真陀螺，这两件事可以分开：**图像负责"想去哪"，陀螺负责"别摆"**。

### 现成参考：HammerTa 的 `gyroscope.c`（244 行）

`HammerTa-17thTC264` 里有一份完整的 ICM20602 用法，路径 `.research_refs\HammerTa-17thTC264\intelegent_car_race_program_17-master\CODE\gyroscope.c`，**而且它的摄像头引脚和我们完全一致**（`MT9V03X_W/H = 188/120`、VSYNC `ERU_CH3_REQ6_P02_0`、PCLK `ERU_CH2_REQ14_P02_1`、数据 `P00_0` 起），说明同一种车模同一种接线，硬件上不用改。

它的三件套值得照抄**结构**：

```c
void ICM20602_GetData(S_INT16_XYZ *GYRO, S_INT16_XYZ *ACC)   // 取数
void ICM20602_Offset(void)                                    // 上电静止 Count 次求均值作零偏
void Data_Filter(void)                                        // GYRO_FILTER_NUM=2 的滑动平均
```

`ICM20602_Offset()` 正好补上我上面留的"温漂"缺口——**上电后车必须静止 1 秒**做零偏标定，之后所有读数减 `GYRO_Offset`。

⚠️ **但它的换算行是错的，别抄**：

```c
GYRO_Real.X = temp4 / 1.0f*GYRO_FILTER_NUM / GyroRatio;   // ← (temp4/1.0)*N/3.4
for(i = 0; i < GYRO_FILTER_NUM - 1; i ++) { ... }        // ← temp4 是 N 次累加和
```

`temp4` 已经是 `GYRO_FILTER_NUM` 次累加和，正确写法是 `temp4 / GYRO_FILTER_NUM / GyroRatio`，它却写成了**乘** `GYRO_FILTER_NUM`。`GYRO_FILTER_NUM=2` 时等于结果被放大了 4 倍——而它下游的阻尼系数是照着这个错误量纲调出来的，所以"看着能跑"。这正是 `03` 末尾"不要照抄系数"的第 1 条实例：**结构可抄，量纲要自己算**。

### 验证方法

1. **静止**：车放桌上，`Servo_Set_Duty` 对应的舵机 PWM 波形（或 `tft180_show_int`）应该是常数，不随时间游走 → 死区合适。
2. **手转**：慢转车头，舵机打角应平滑跟随反向；快抖车头，舵机只在抖动瞬间出一下力 → 低通系数合适。
3. **直道高速**：先只接陀螺不动 `SERVO_KD`，看直道末端的左右摆动幅度是否变小；再把 `SERVO_KD` 降到 1.2，摆动应进一步变小。若变得更差，说明符号或死区有问题。
4. **对照跑**：`SERVO_GYRO_DAMP_EN 0/1` 各跑 5 圈，记录单圈时间与"出弯超调次数"（肉眼数或看舵机占空比越过 `Servo_MID` 的次数）。

### 风险

| 风险 | 说明与对策 |
|:--|:--|
| **中断里跑 SPI** | `imu660rc_get_quarternion()` 在 EXTI 里做 SPI 读，一次约几十微秒。EXTI 频率 480 Hz 时占用 <3% CPU。若发现 5 ms 节拍抖动，把频率降到 120 Hz 或 `240HZ` |
| **芯片型号不同** | 库里同时有 `zf_device_imu660ra.c`（SPI/IIC）与 `zf_device_imu660rc.c`（IIC+四元数）。先确认手上是 RA 还是 RC：**RC 才有内置四元数解算**，RA 只有原始三轴，那就用 `imu660ra_get_gyro()` 且不要指望 `yaw` |
| **IIC/SPI 引脚冲突** | 上表按 `推荐IO分配.txt` 给的 SPI0 是 **ICM20602** 的接法；IMU660RC 走 IIC 时占 P20_11/P20_12（SCL/SDA）。接之前先确认车上到底焊的是哪一颗 |
| **阻尼把车"顶死"** | `IMU_GZ_K` 起点给 0.010，若直道像被手按住一样发闷、弯道进不去，说明过大；按 0.005 / 0.010 / 0.020 三档试 |
| **温漂** | 陀螺零偏随温度漂，静止读数可能偏几百 LSB。上面用死区 + 低通兜住了；若仍偏，加一个上电静止 1 s 求均值的零偏标定（参考 `Control_REMAIN.c:245-262` 已有的"发车前 1000 ms 编码器噪声标定"写法） |

## C1 · 元素识别四层结构（P2）

### 现状

`code/MIDLine_REMAIN.c:223-281` 只识别十字：宽度 > 学习宽度×1.25（`:223`）、有效行<12 且宽度>1.1×（`:227-231`）、中线偏出±30 像素否决（`:232-235`）、连续 2 帧锁 40 帧（`:254-258`）、锁定期间强制直行（`:273-281`）。

其余元素（环岛/三叉/坡道/车库/断路/避障）**全部缺失**。

### 目标

不逐个加 `if`，而是先把 17th-SmartCar 的四层结构搭起来，再往里填元素。

```
第 1 层  路线先验（dieReady）      车知道"下一个该是什么" → 开放识别降为确认
第 2 层  标志互斥门                任何时刻只有一个元素标志可置位
第 3 层  几何否决                  几何不符直接否掉，不进状态机
第 4 层  前摇分诊                  用拐点几何一次性分类，避免每个元素各写一套特征
```

参考：`17th-SmartCar\CODE\Camera.c:119`（`dieReady`）、`:1738`（互斥门）、`:1742-1805`（几何否决）、`:2565-2648`（`Windup` 前摇分诊）。

### 具体改法

新增 `code/Element_REMAIN.h`：

```c
#ifndef CODE_ELEMENT_REMAIN_H_
#define CODE_ELEMENT_REMAIN_H_

#include "zf_common_headfile.h"

typedef enum {
    ELEM_NONE = 0,
    ELEM_CROSS,         // 十字
    ELEM_ROUND_LEFT,    // 左环岛
    ELEM_ROUND_RIGHT,   // 右环岛
    ELEM_FORK,          // 三叉
    ELEM_RAMP,          // 坡道
    ELEM_GARAGE,        // 车库
    ELEM_BREAK,         // 断路
    ELEM_ZEBRA,         // 斑马线（已有）
    ELEM_MAX
} elem_id_enum;

typedef enum {
    ELEM_ST_IDLE = 0,
    ELEM_ST_ENTER,      // 已确认，正在进入
    ELEM_ST_INSIDE,     // 在元素内部
    ELEM_ST_EXIT,       // 正在退出
    ELEM_ST_DONE        // 已完成，等待复位
} elem_state_enum;

typedef struct {
    elem_id_enum    id;
    elem_state_enum state;
    uint16_t        frame_cnt;      // 当前状态持续帧数
    uint16_t        timeout_cnt;    // 超时计数器（防死锁）
    uint32_t        encoder_sum;    // 进入时的编码器里程，用于里程预算
    float           geometry[4];    // 拐点几何（前摇分诊的输入）
} elem_ctrl_struct;

extern elem_ctrl_struct elem_ctrl;
extern elem_id_enum     die_ready;      // 路线先验

void          Element_Init(void);
void          Element_Scan(void);       // 每帧调用：填 geometry，跑四层判据
void          Element_Act(void);        // 每帧调用：按 state 改中线/速度
elem_id_enum  Element_Diagnose(void);   // 第 4 层：几何 → 元素类型
void          Element_Reset(void);      // 全局复位（按键/丢线超时）

#endif
```

`code/Element_REMAIN.c` 骨架：

```c
#include "Element_REMAIN.h"

elem_ctrl_struct elem_ctrl;
elem_id_enum     die_ready = ELEM_NONE;

// 第 2 层：互斥门。任何时刻只有一个元素在非 IDLE 状态
static uint8_t elem_gate_open(void)
{
    return (elem_ctrl.state == ELEM_ST_IDLE || elem_ctrl.state == ELEM_ST_DONE);
}

// 第 3 层：几何否决。把"不可能"的情况先排掉，降低第 4 层负担
static uint8_t elem_geometry_veto(elem_id_enum id)
{
    switch (id) {
        case ELEM_ROUND_LEFT:
        case ELEM_ROUND_RIGHT: {
            // 环岛：一侧边线的丢线行数必须显著多于另一侧，且视距内无对侧拐点
            if (bedline_lost_cnt_l < 10 && bedline_lost_cnt_r < 10) return 1;   // 否决
            if (bedline_confidence < 0.5f) return 1;                            // 否决
            return 0;
        }
        case ELEM_BREAK: {
            // 断路：两侧同时丢线且中线置信度极低
            if (midline_confidence > 0.3f) return 1;
            return 0;
        }
        case ELEM_RAMP: {
            // 坡道：俯视图无法判（A1 的副作用），只信陀螺仪
            if (fabsf(gyro_pitch) < 2.0f) return 1;                              // 2°，参考 17th 的 Emo_Pitch>=2
            return 0;
        }
        default:
            return 0;
    }
}

// 第 4 层：前摇分诊。用拐点几何一次性分类
elem_id_enum Element_Diagnose(void)
{
    // geometry[0..1]: 左/右边界拐点的 (行, 列)
    // geometry[2]: 边界宽度突变比
    // geometry[3]: 视距内拐点数量

    if (elem_ctrl.geometry[3] >= 2 && elem_ctrl.geometry[2] > 1.25f) return ELEM_CROSS;
    if (elem_ctrl.geometry[2] > 1.8f)                                 return ELEM_FORK;
    if (bedline_lost_cnt_l > 15 && bedline_lost_cnt_r < 5)            return ELEM_ROUND_LEFT;
    if (bedline_lost_cnt_r > 15 && bedline_lost_cnt_l < 5)            return ELEM_ROUND_RIGHT;
    return ELEM_NONE;
}

void Element_Scan(void)
{
    // 第 1 层：路线先验。若 die_ready != NONE，只确认那一个元素
    // 第 2 层：互斥门
    if (!elem_gate_open()) {
        elem_ctrl.frame_cnt++;
        // 超时保护：任何状态最多持续 300 帧（约 6s @50fps）
        if (++elem_ctrl.timeout_cnt > 300) Element_Reset();
        return;
    }

    elem_id_enum cand = (die_ready != ELEM_NONE) ? die_ready : Element_Diagnose();
    if (cand == ELEM_NONE) return;

    // 第 3 层：几何否决
    if (elem_geometry_veto(cand)) return;

    // 去抖：连续 2 帧命中才确认（沿用本工程十字的成熟做法 MIDLine_REMAIN.c:254-258）
    if (elem_ctrl.id != cand) {
        elem_ctrl.id = cand;
        elem_ctrl.frame_cnt = 0;
        return;
    }
    if (++elem_ctrl.frame_cnt < 2) return;

    elem_ctrl.state = ELEM_ST_ENTER;
    elem_ctrl.timeout_cnt = 0;
    elem_ctrl.encoder_sum = encoder_total;
}

void Element_Reset(void)
{
    elem_ctrl.id = ELEM_NONE;
    elem_ctrl.state = ELEM_ST_IDLE;
    elem_ctrl.frame_cnt = 0;
    elem_ctrl.timeout_cnt = 0;
}
```

### 补一层"场景分类"：`room` 连通域计数

`losehu` 的元素判据有一个前置层，值得加在四层结构之前（`image_deal.c:1996-2088`）：

**数二值图里"黑色连通域"的数量**（行方向扫描 + 并查集或标号传播），得到 `room`。它的实测对应关系：

| `room` | 场景 |
|:--:|:--|
| 2 | 直道 / 普通弯（左右各一条边） |
| 4 | 环岛（多两条圆弧） |
| 6 | 三叉 |
| 8 | 十字 |

这个数字**比任何单一判据都稳**，因为它是对整幅图的全局计数，不受单行噪声影响。代价是要一次标号传播（188×120 → 用行扫描 + 并查集，约 8~15 ms，**必须放 CPU1**）。

**注意**：这 2/4/6/8 是它自己赛道、自己视野下的值，换到我们要重标——先只把 `room` 打进屏显，跑三天数据看分布，再定阈值。

### 落地顺序（重要，不要一次全写）

1. **只搭框架**：把现有十字逻辑搬进 `ELEM_CROSS` 分支，其余元素返回 `ELEM_NONE`。跑一圈确认行为和改造前完全一致——**这一步是纯重构，不改变行为，必须零回归**。
2. **加断路 `ELEM_BREAK`**：判据最简单（两侧同时丢线），且能立刻解决"A2 的 `continue` 改造后，长距离丢线仍会跑飞"的问题。
3. **加环岛**：参考 ZongZuanFeng 的 4 态（`Camera.c:722-764`，ENTRY→INSIDE→EXIT，EXIT 需连续 8 帧稳定且禁回退）或 wuyou33 的"以一侧拐点虚构另一侧边界"。**先只做一种方向**（wuyou33 也是只做左环）。
4. **加三叉**：参考 17th 的"边界局部极值平台"（`Camera.c:1424-1536`）。
5. **加坡道**：必须走陀螺仪（A1 之后俯视图看不到坡道）。
6. **加车库**：最后做，它依赖"速度-目标行"查表（参考 17th `stop_PHIone`，`Camera.c:1928-1988`）。

### 验证方法

- 每个元素单独测，**用 `die_ready` 强制指定**（先验把开放识别变成确认），确认状态机能走完 `IDLE→ENTER→INSIDE→EXIT→DONE` 且不超时。
- 再关掉 `die_ready`（置 `ELEM_NONE`）测开放识别，看误判率。
- 全程记录 `elem_ctrl.state` 到屏上，任何一次"停在 ENTER 不动"或"EXIT 后回不到 IDLE"都是状态机 bug。

### 风险

- **超时保护是必须的**：xiayu 的 `Max/Max2` 从不复位 → 进过一次环后恒误判；wuyou33 靠 `Circleprotect()` 里程兜底但会 `0/0` 除零。本设计用 `timeout_cnt > 300` 统一兜底。
- **`die_ready` 依赖赛道记忆**：正式比赛如果赛道顺序有随机性，这一层失效，第 4 层的开放识别必须能独立工作。

for (i = 0; i < MT9V03X_H; i++) {

## D2 · CPU1 承接图像处理（P3）

### 现状

`user/cpu1_main.c:46-64`：

```c
void core1_main(void)
{
    cpu_wait_event_ready();
    // 完全空
}
```

**CPU1 100% 闲置**，而 CPU0 独自承担采集 + 二值化 + 边线 + 元素 + 控制。对比 TC264-ZongZuanFeng：CPU0 独占 MT9V03X + IPS200 + UART（感知核），CPU1 跑 PIT 10ms 控制环。

### 目标

CPU0 = 感知核（采集 + 逆透视 + 二值化 + 边线提取），CPU1 = 控制核（控制环 + 元素状态机 + 显示）。

### 具体改法

把 TC264-ZongZuanFeng 的 `Shared.h:23-26` 模式搬来（**只有 4 个裸 `volatile`**），但**必须解决本工程的既有缺陷：主循环与中断共享 `midline_info` 无临界区**（`00` 文档缺陷 #12）。

推荐用**双缓冲 + 序号校验**，比关中断更安全：

```c
// code/Shared_REMAIN.h
typedef struct {
    float   mid_line_center;
    float   error;
    uint8_t valid;
    uint8_t confidence_x100;
    uint8_t elem_state;
    uint8_t frame_id;
} shared_midline_struct;

extern volatile shared_midline_struct shared_midline[2];    // 双缓冲
extern volatile uint8_t            shared_write_idx;        // 生产者在写哪一块
extern volatile uint8_t            shared_seqn;             // 每次写完 +1（奇数=正在写）

// CPU0（生产者）每帧末尾：
static void shared_publish(const shared_midline_struct *src)
{
    uint8_t idx = shared_write_idx ^ 1;
    shared_seqn++;                                          // 变奇数，消费者放弃读取
    shared_midline[idx] = *src;
    shared_write_idx = idx;
    shared_seqn++;                                          // 变偶数，消费者可读
}

// CPU1（消费者）每次读取：
static uint8_t shared_consume(shared_midline_struct *dst)
{
    uint8_t s0 = shared_seqn;
    if (s0 & 1) return 0;                                   // 正在写，本拍沿用旧值
    *dst = shared_midline[shared_write_idx];
    return (shared_seqn == s0);
}
```

这套"序号"模式（seqlock）比关中断好在：**读侧永远不阻塞，最坏情况是丢一帧**。对控制环来说丢一帧比卡 100us 更好。

### 验证方法

1. 压力测试：CPU0 跑满图像链的同时 CPU1 以 200Hz 读，连续 10 分钟统计 `shared_consume()` 返回 0 的次数，应 < 0.1%。
2. 用 STM 定时器测 CPU0 的单帧耗时，改前/改后对比（预期降到 40%~55%）。

### 风险

- **中断归属必须重排**：`user/isr_config.h` 里 PCLK（摄像头 DMA 触发）现在挂在哪就留在哪，但 PIT 控制中断要让 CPU1 接管。参考 ZongZuanFeng 的分配表：CCU6_0→cpu0、CCU6_1→cpu1、PCLK→`IfxSrc_Tos_dma`、VSYNC→cpu0、DMA ch5→cpu0。
- CPU1 的 printf/浮点也要确认可用（TC264 双核共享 FPU，但上下文切换有开销）。

## 执行建议

### 三轮迭代

| 轮次 | 内容 | 验收标准 |
|:--|:--|:--|
| **第 1 轮**（半天 + 1 天） | C2 第 1 步（启用 seekfree_assistant 遥测）+ **B4 陀螺仪接入** | 能看到 8 条波形曲线；`imu660rc_gyro_z` 读数正常且手转车头有响应 |
| **第 2 轮**（3~5 天） | A1 逆透视 + A2 补线回写 + D1 | 直道边线竖直平行；弯道不提前弯折 |
| **第 3 轮**（1~2 周） | B1 + B2 + B3 + C1（先只框架 + 断路） | 圈速提升，参数可在线调 |

> **B4 为什么塞进第 1 轮**：它只加 35 行、不改变任何现有信号的量纲、失效时可以一个宏关掉（`SERVO_GYRO_DAMP_EN 0`），却直接改善"车摆"这个最影响圈速的问题。A1 会改变 `error` 的分布，B4 不会——所以它可以和 A1 并行，不违反下面"不要同时改两处"的规矩（它改的是完全独立的一条通路）。

### 三个"半行到两行"的低成本改动（可随时插入任何一轮）

| 改动 | 位置 | 效果 |
|:--|:--|:--|
| **航向环降频到图像帧率** | `Control_REMAIN.c:326` 的 `Servo_Set_Turn(error)` 加一个"新帧标志"门控 | 图像才 50 fps，5 ms 舵机有 3/4 的拍子在重复算同一偏差。降频后省下的 CPU 直接留给元素识别（`losehu` 就是这么干的：速度环 1 ms，航向环事件驱动） |

### 每一步都要留回归基线

改造前先记录一组"基线波形"（`error` / `duty` / `actual_speed` / `camera_threshold` / `midline_info.valid`）存成 CSV。每次改完录一组新的做对比——**这是唯一能证明"改对了"的方法**，否则所有优化都是体感。

### 禁止的三件事

1. **不要同时改两处**。A1 与 B3 都会改变 `error` 的量纲/分布，一起改将无法归因。
2. **不要照抄系数**。USTB_Swan 的 `target*13`、17th 的 `Straight[120]` 87→15、wuyou33 的 `Weight[60]` 峰值 7 —— 这些都是各自车模、各自视野、各自速度下的值。抄结构，不抄数字。
3. **不要相信参考仓库的"能跑"**。本清单里列出的每一个坑（wuyou33 的假增量、xiayu 的假补线、17th 的 `Camera_Pro()` 无调用、USTB 的 `Kdd` 恒 0）都是**看起来完全正常但完全不生效**的问题。抄之前先用本工程的量纲核算一遍。
